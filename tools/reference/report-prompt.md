このフォルダ（カレントディレクトリ）にあるリファレンス曲の分析レポート `report.md` を書いてください。

## 手順

1. **`analysis/gates.json` を最初に読む。** 分析がどこまで信用できるかの判定はすべてここに出してある（下記）
2. `TOOLS/report-template.md` を読む。**節構成・各行のJSONキーの対応・判定語の閾値がすべてそこにある。**
   閾値は曲をまたいで目盛りを揃えるための取り決めなので、**勝手に別の線を引かない**
3. `TOOLS/report-example.md` を読む。書きぶりの見本（別の曲で実際に書いたもの）
4. `analysis/` 配下の JSON を読む。数値は**必ず JSON から取る**。記憶や推測で書かない
5. `report.md` を書く

## 信頼性のゲート

`analysis/gates.json` に判定済み。各項目の `ok`（bpm だけ `octave_ok`）を見て、
**false の項目は数値を書かず「測れなかった」と明示する**。

| キー | false のとき |
|---|---|
| `bpm.octave_ok` | **レポートを書かず、その旨だけ報告して終了**（グリッドが違うと全分析が無意味） |
| `tempo_stable.ok` | 「テンポが揺れており小節番号は後半ほど信用できない」と明記 |
| `downbeat.ok` | 小節頭の位置が疑わしい。16分プロファイルの解釈を書かない |
| `swing.ok` | 「ハネ無し」と書かない。「ハットが無く測定できず」と書く |
| `harmony.ok` | ハーモニーの節は「上モノがほぼ無いため推定しない」とし、代わりに何で構成されているかを書く |
| `key.confidence` | 「中」「低」ならその確度を明記する |

`harmony.ok` が true のときは `harmony.source_stem` のステムの進行を採用する
（他のステムは音量が足りず、同じかぶりノイズを見て揃って誤答することがある）。

**この判定を自分でやり直さないこと。** DSP を再導出したり `basics.py` などの実装を読みに行ったりせず、
`gates.json` の結論をそのまま使う。仕事は分析の再検証ではなく、レポートを書くこと。
分析スクリプトの中身は読まなくてよい。

## 書き方

- 雛形の `【機】` はJSONからの転記、`【判】` は判断。**`【判】` を埋めるのが仕事の本体**
- ラベル（「Rhodes＋808」）で終わらせず、**因果で書く**。「なぜその数値が、その聴こえ方になるか」
- 数値を出したら、その値である理由か意味を一言添える
- 「定石」と「この曲の癖」を切り分ける。曲の個性は大抵「癖」側にある
- 同じ主張を2回説明しない。2回目以降は結論だけ参照する
- 見出しは分析項目名でなく結論にする
- 曲の話とツールの話を混ぜない。トリム・信頼度・レビュー依頼は `---` 以下の付録へ

雛形の最後の節「`「<本人が使った言葉>」は何でできているか`」は、本人がこの曲をどう呼んでいるかが
分からなければ「**この曲の性格は何でできているか**」として書く。

## 出力

`report.md` を書いたら、最後に次の3点だけを短く報告する。

- 採用した BPM・キー・ループ長
- ゲートに引っかかった項目（あれば）と、レポートでどう扱ったか
- 耳で確かめてほしい箇所（`listen/` のどれを聴けばよいか）
