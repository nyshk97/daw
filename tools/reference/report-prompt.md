このフォルダ（カレントディレクトリ）の `report.md.next` は、リファレンス曲の分析レポートのドラフト。
数値・表・判定語（【機】）は report.py が analysis/*.json から機械充填済みで、
残っているのは判断と文章（【判】）だけ。あなたの仕事はその【判】を書き上げること。

## 手順

1. `report.md.next` を Read する
2. 【判】を Edit で埋める:
   - 山括弧の可視プレースホルダ 〈…〉 を**すべて**自分の文章・判断語に置き換える（見出しの中のものも含む）
   - 本文型: 「判:名前:start / end」の HTML コメント対の**内側**に文章を書く
   - インライン型（表セル内）: 「判i:名前:start / end」の間のプレースホルダを判断語に置き換える
   - **マーカー（HTML コメント）はどちらの型も消さない**。各マーカー位置のコメントに、その節で
     何を書くかの指示がある
   - **機械充填済みの数値・表・判定語は書き換えない**（転記と線引きは report.py の仕事。
     おかしいと思ったら本文を直さず、最後の報告で指摘する）
3. 書き終えたら、次の3点だけを短く報告する:
   - 採用した BPM・キー・ループ長
   - ゲートで「測れなかった」扱いの項目（ドラフトに焼き込み済み。あれば）
   - 耳で確かめてほしい箇所（listen/ のどれを聴くか）

## 判断材料

- 必要な数値は、ドラフトの充填値とこのプロンプト末尾の**ダイジェスト**に全部ある
- 足りない値があるときだけ `analysis/` 配下の JSON を Read してよい。ただし:
  - **分析の再検証・DSP の再導出・分析スクリプト（*.py）を読むことはしない。**
    ゲート判定はドラフトに焼き込み済みで、やり直さない。仕事は検証ではなく執筆
  - `chords[]`（区間ごとの生推定）は読まない。進行はドラフトの表（畳んだ進行）がすべて
- **作文の禁止**: ヘッダ行・本文に、渡された情報に無いこと（プロデューサー・レーベル・
  リリース年・逸話等）を書かない。分からないものは書かない

## 書き方

- ラベルで終わらせず**因果で書く**。「なぜその数値が、その聴こえ方になるか」
- 音楽用語は初出に一言注釈を付ければ使ってよい。**分析ツールの内部用語（ラグ・ステム等）と
  独自の比喩（「家」等）は使わない** — 比喩より動作の描写（「毎ループここに戻る」）で書く
- 数値を出したら、その値である理由か意味を一言添える
- 「定石」と「この曲の癖」を切り分ける。曲の個性は大抵「癖」側にある
- 同じ主張を2回説明しない。2回目以降は結論だけ参照する
- 見出しは分析項目名でなく結論にする
- 曲の話とツールの話を混ぜない
- 最終節の見出し「〈本人が使った言葉〉は何でできているか」は、本人がこの曲をどう呼んでいるか
  分からなければ「**この曲の性格は何でできているか**」とする

この下に**見本**（別の曲の完成品）と**ダイジェスト**（この曲の分析値）が続く。
