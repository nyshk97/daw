## 2026-08-21 — Phase 0: 検出と再合成の聴き比べ

### 評価軸（耳判定の前に固定）

各 1〜5（5 が良い）。ブラインド（W/X/Y/Z に伏せた4エンジン）で素材 × ケースごとに採点する。

| 軸 | 何を聴くか | 対象ケース |
|---|---|---|
| ①滲み | 声が二重にぼやける・水っぽい（位相ボコーダー特有の位相の乱れ） | A/B/C/D |
| ②子音・息 | s/k/息の荒れ・にじみ・消失 | 全ケース |
| ③声質 | 細く/太くなる・別人感（フォルマント崩れ） | Z/A/B/C |
| ④ケロらしさ | ハードチューンとして「使える」音か | C |
| ⑤透明性 | 無加工（補正量0）が原音と区別つかないか | Z |
| ⑥境界 | 横移動した音の前後にクリック・二重化・もたつきが無いか | D |

ケース: Z=無加工 / A=スケールスナップ・強さ100%・速さ120ms / B=A＋全体+3半音 / C=ケロケロ（速さ0ms）/
D=A＋1音を +40ms 横移動（隣接の隙間が吸収）。

判定手順（plan）: 候補3エンジン（signalsmith / PSOLA ハイブリッド / WORLD）は**ケース D を通過**
（出力サンプル数一致・境界クリック/二重化なし・⑥が3以上）が足切り。通過者を A → C → B の順で順位付け。
Rubber Band R3 は GPL のため**天井の参照のみ**（順位付け対象外）。

検出側の合格線（plan）: 合成素材で GPE < 3%・voicing precision ≥ 0.95・recall ≥ 0.90、
実声で目視の明らかな誤り（オクターブ飛び・有声/無声の取り違え）がノート数の 10% 未満かつ連続しない。

### 検出: 数値結果（AI・2026-08-21）

自作 YIN（`tools/pitchlab/yin.py`: 差分関数→累積平均正規化→絶対閾値 0.15→放物線補間。有声度 = 1 − d'min、
有声閾値 0.6）を pYIN（librosa）・CREPE（torchcrepe full）と比べた。hop 5ms・フレーム 2048（42ms）。

**合成素材（正解あり）**

| 検出器 | GPE（半音以上外した割合） | 微小誤差の中央値 | voicing precision | voicing recall |
|---|---|---|---|---|
| 自作 YIN | **0.0%** | 1.4 cent | **0.992** | **0.994** |
| pYIN | 0.0% | 1.5 cent | 0.959 | 1.000 |
| CREPE | 0.0% | 4.7 cent | 0.945 | 1.000 |

読み方: GPE 0% = 3検出器とも音程を大きく外したフレームが無い。precision は「有声と言ったうち本当に有声」の
割合で、pYIN/CREPE は 0.95 前後＝ノイズバーストや息の端を 5% ほど有声に取っている。YIN は 0.99 で
息をノートにしにくい（plan の「precision 優先」に合う）。合格線（GPE<3%・P≥0.95・R≥0.90）を YIN は満たす。

**実声（正解なし。検出器同士の不一致率）**

| 素材 | 比較 | 音程不一致（両者有声のうち半音以上違う） | うちオクターブ飛び | 有声/無声の食い違い |
|---|---|---|---|---|
| rap 4–12s | YIN〜pYIN | 1.4% | 0.2% | 6.9% |
| rap 4–12s | YIN〜CREPE | 1.3% | 0.2% | 8.6% |
| rap 4–12s | pYIN〜CREPE | 0.2% | 0.0% | 5.0% |
| uta 7.5–15.5s | YIN〜pYIN | 1.0% | 0.0% | 6.1% |
| uta 7.5–15.5s | YIN〜CREPE | 1.4% | 0.0% | 7.5% |
| uta 7.5–15.5s | pYIN〜CREPE | 0.3% | 0.0% | 3.3% |

読み方: 音程は3者ほぼ一致（1% 台・オクターブ飛びは実質ゼロ）。差は有声/無声の境界（6〜9%）で、
YIN が語頭・語尾を数フレーム短めに取る傾向（`pitch-correction-outputs/*-overlay.png` 下段）。
有声閾値は 0.5〜0.8 を掃引し、0.8 では rap の recall（pYIN∧CREPE の合議に対して）が 0.63 まで落ち、
0.6 で P 0.97 / R 0.90〜0.94 になったので 0.6 を採用。**目視ラベル（人間）で致命的な誤りが無ければ
自作 YIN で進む**。CREPE（torch 依存・推論 27s の素材で 1〜2 分）をアプリに入れる理由は無い。

ノート分割（`notes.py`）: 直近 40ms の中央値がノートの中央値から 0.5 半音以上離れた状態が 90ms 以上続いたら
切る（90ms はビブラート半周期 5〜6Hz より長く、深さ 60cent のビブラートで割れない値。30/40ms だと
合成素材のビブラート音が 10 音→28 音に割れた）。60ms 未満は隣へ吸収。合成素材は 10 音ちょうどに分かれ、
中央値はデチューン込みの真値と ±5cent で一致。実声は rap 33 音（中央値 165ms）・uta 27 音（185ms）
（`pitch-correction-outputs/*-notes.png`）。

### 再合成: 数値結果（AI・2026-08-21）

4エンジン × ケース Z/A/B/C/D（`resynth.py`。`work/<素材>/resynth/verify.json`）。
達成誤差 = 出力を YIN で再検出し |実測 − 目標| の中央値 / 95%点[cent]（境界 ±15ms は除外）。

| ケース/素材 | PSOLA（自作） | WORLD | signalsmith | Rubber Band R3（参照） |
|---|---|---|---|---|
| Z 透明性 max\|wet−dry\|（合成/rap/uta） | **0 / 0 / 0（ビット一致）** | 0.73 / 0.41 / 0.25（再合成臭） | 6e-5 / 7e-4 / 9e-5 | 0.14 / 0.03 / 0.01 |
| A 合成 med/p95 | 1.8 / 8.5 | 0.8 / 3.8 | 4.4 / 24.7 | 5.1 / 27.3 |
| A rap | 15.0 / 82 | 5.6 / 38 | 14.2 / 89 | 19.7 / 110 |
| A uta | 6.5 / 70 | 2.4 / 32 | 10.5 / 73 | 12.7 / 81 |
| B（+3半音）uta | 6.7 / 70 | 2.3 / 33 | 10.2 / 72 | 11.7 / 80 |
| C ケロケロ 合成 | 1.1 / 3.8 | 1.2 / 5.1 | 10.2 / 86 | 15.0 / 97 |
| C ケロケロ rap | 10.8 / 77 | 6.3 / 53 | **47 / 183** | **57 / 211** |
| C ケロケロ uta | 4.8 / 62 | 3.7 / 65 | **36 / 211** | **42 / 236** |
| D 長さ一致 | ✓ | ✓ | ✓ | ✓（今回の map では一致） |
| D クリック比（入力の最大差分に対する比） | 0.73〜1.0 | 0.96〜1.07 | 0.72〜0.94 | 0.72〜0.98 |

読み方:
- **ケロケロは位相ボコーダー系（signalsmith / Rubber Band）が追えない**（中央値 36〜57cent・p95 2 半音超）。
  フレームごとに変わるシフト量をブロック単位でしか更新できず、内部の平滑化で平らにならない。PSOLA と
  WORLD は周期単位で追うので平らになる（合成で 1cent）。ケロケロを同じエンジンで持つ plan の前提上、
  **位相ボコーダー単独は候補から落ちる**可能性が高い（耳で確認）
- 実声の p95 が 60〜110cent と大きいのは、語尾のグライド・語頭の立ち上がり（目標が 5ms 単位で急変する
  箇所）の再検出ずれが主で、持続部は中央値どおり（`*_verify.png` で確認）。WORLD が最小なのは自前の
  f0 を直接書き換えて再合成するため（=音程は正確だが Z で 0.25〜0.73 の差＝無加工でも声が作り直される）
- PSOLA は無加工でビット一致（「補正量 0 のフレームは素通し」を構造で保証）。signalsmith は 16bit WAV
  経由で 1e-4 台（実質透明）
- クリック比は全エンジン 1.1 以下＝境界のクリックは数値上は出ていない。二重化・もたつきは耳で判定

実装メモ（罠）:
- signalsmith `cmd/util/wav.h` の `length()` は `offset` を引いた残量を返す。ループ中に offset を進めた
  後に総長のつもりで呼ぶと半分以降の入力が尽きて出力が崩れる（4.5s 以降が一定のスミアになった）
- PSOLA の「次の入力マークへ同期」は同じ有声区間（1.5 周期以内）に限る。隣の区間の先頭マークへ飛ぶと
  間の無声区間（子音バースト）が丸ごと欠ける
- pyworld 0.3.5 は `pkg_resources` を import するため setuptools<81 が要る
