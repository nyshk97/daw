# ドラムパターンの制作条件（2026-08-22 確定）

ドラムステム単体でのブラインド聴取（正例23・否定例10）と、同一素材で1性質だけ動かした
A/B検証から確定した条件。根拠と限界は[labs/drum-pattern.md](../labs/drum-pattern.md)。

## 一言でいうと（本人の言葉）

> キックが1と3、スネアが2と4、ハイハットが8分で均等なビートが典型的な好きなビート。
> そこから多少アレンジしたものも好き。
> 逆にハイハットが高密度かつ大きな音で鳴りまくってるのが苦手。

以下はこれを測れる形にしたもの。**「典型」が基準・「苦手」が境界**で、
その間（アレンジの幅）が自由に振ってよい範囲になる。

## 確定した境界

> **はっきり鳴るハットが毎秒4打点前後を超えると「うるさい」。
> 打点の総数ではなく、はっきり鳴っている数だけが効く。音量を落とした打点は何回足してもよい。**

否定5本 4.16–4.86 / 肯定19本 1.16–4.05（最密4小節）で重なりゼロ。
A/Bでは、打点の数も位置も同じで**追加分の音量だけ−12dBにしたパターン**が
「うるさい」から「許容」へ移った。

### テンポ別の上限

境界は実時間なので、同じ譜面でもテンポで結果が変わる。

| BPM | 1小節の秒数 | はっきり鳴らせる上限（打点/小節） | 実務的な意味 |
|---:|---:|---:|---|
| 85 | 2.82 | 11.3 | 8分＋3つまで足せる。16分の埋め尽くしはアウト |
| 92 | 2.61 | 10.4 | 8分＋2つ |
| 110 | 2.18 | 8.7 | 8分＋0.7。**足す余地がほぼ無い** |
| **120** | 2.00 | 8.0 | **分岐点。8分がちょうど上限で足せない** |
| 130 | 1.85 | 7.4 | **8分でもアウト**。4分＋アクセントへ落とす |

Missing You（89BPM・8分）が「等間隔で良い」、タクシードライバー（130BPM・8分）が
「あんま好きじゃない」になった差がこれ。譜面は同一。

**16分の均一刻み（16打点/小節）が境界内に収まるのは60BPM以下**なので、
hiphopのテンポ帯では原理的に常にアウト。トラップのハットロールが成立するのは
必ず音量差がついているからで、均一な音量でやればどのテンポでもうるさくなる
（A/Bで最下位だった `all_16th` がこれ）。

### 本命のテンポ帯（2026-08-22 正例23曲の実測）

上限が実時間で決まる以上、テンポの選択がそのままドラムの自由度を決める。

```
正例23曲のBPM  中央値 89 / 四分位範囲 84–97 / 80–95に16曲
```

160BPMと記録されている3曲（YourSong・Made my day・EXPLAIN）はハーフタイムなので
80として数えている。**ドラム判定が最高（+2）だった7曲は全部94BPM以下。**
唯一の否定（タクシードライバー）が130BPM。

- **85–95 が本命**。この帯なら8分ハットが余裕で境界内に収まる
- **100を超えると条件が厳しくなる**。110で8分がほぼ上限
- **130前後は、ハットの扱いを変えないと好みから外れる**。8分刻みですら境界を超えるので、
  4分へ落とすかゴーストにする必要がある

曲数23の傾向なので線ではなく帯。134BPMのLONELY NIGHTSは+1（割と好き）だった。
なお本人の事前の体感とも一致している（分布を見る前に「そのくらいだと思っていた」）。

### 使い方

- **ハットを増やしたいときは音量を落とす**。数ではなく「はっきり鳴っている数」が効く
- **テンポを上げたら、はっきり鳴らすハットを減らす**。BPMを上げてパターンを据え置くと境界を越える
- **最も避けるべきは、均一な音量で細かく刻み続けること**。否定側5本はハットの音量差が
  ほぼゼロ（0.00–0.81）で、肯定側には強弱のある曲が多い（最大3.23）

強弱があること自体は条件ではない。肯定側にも音量差ゼロの曲がある（Missing You・Made my day）。
効くのは**はっきり鳴る数の上限**であって、ゴーストの有無ではない。

## 基準となるパターン（2026-08-22 本人が特定）

制約（何がダメか）と基準（何が典型か）は別物で、生成器には両方が要る。
検証用に合成した4本のうち、本人が**「一番典型的な、好きなドラムパターンの例」**と挙げたのが
`sparse_even`（`review/drum-ab-kick/` の T）。

```
        1   e   &   a   2   e   &   a   3   e   &   a   4   e   &   a
ハット   x       x       x       x       x       x       x       x      8分・全部同じ音量
スネア                   x                               x              2拍4拍
キック   x                               x                              1拍3拍
```

92BPM でハット3.07打点/秒。最も素朴な boom bap の骨格で、キックとスネアが完全に交互、
ハットが完全に等間隔。**打点が全部予測できる位置にあるのでドラムへ注意が向かない**。
ラップと上モノを主役にする chill hiphop では理にかなった配置で、
本人が「淡々としてる」を褒め言葉として使うのと符合する。

**ガチャはここを中心に振る。** 現行のデフォルト profile は既にこの隣にある。

```python
"kick_profile_by_beat":  [1.0, 0.25, 0.85, 0.25]    # 1拍目は必ず・3拍目85%・裏拍は25%
"hat_profile_by_16th":   [1.0, 0.0, 0.75, 0.0] * 4   # 8分。表1.0・裏0.75
```

ただしこの hat profile が境界内に収まるのは 92BPM での話で、
130BPM なら同じ profile が 4.32打点/秒になって境界を超える（生成器がBPMを見る必要があるのはこのため。
[issue #9](https://github.com/nyshk97/daw/issues/9)）。

## ドラムガチャの役割（2026-08-22 転換）

基準パターンが1つに確定したことで、ガチャの役目が変わった。1・3キック / 2・4スネア / 8分ハットは
手で打てば30秒で、ガチャで引き当てる必要がない。**価値は「基準を出すこと」ではなく
「自分では思いつかない崩し方を見せること」にある。**

- **崩しは1小節の中の配置と、小節をまたぐ変化の両方**でやる。後者は現行ゼロ
  （`_generate_bar` の結果を bars 回そのままコピーしている＝4小節ループの4小節目が1小節目と完全に同じ）
- **つまみは作らない**。候補を「基準に近い順」に並べ、下へ行くほど崩れる形にする。
  「どれだけ崩すか」は「何番目を選ぶか」に吸収される
- **崩す方向は既存のレーンロックで指定する**（キックを固定すればハットだけ崩れる）

## レーン = サンプル1個（MPCのパッド）

ドラムのレーンを「楽器」ではなく**サンプル1個**と定義する。ハット強とハット弱は別レーン。
実物のハイハットは強く叩くと音色自体が変わる（倍音が増えて明るく長くなる）ため、velocity を
下げただけでは弱打の音にならず「同じ音が遠くで鳴っている」に聞こえる。市販のドラム音源がどれも
強弱で別サンプルを持つ（ベロシティレイヤー）のはこのため。

このモデルにすると3つが同時に解ける。

- **発音確率と velocity の分離が実装なしで済む**。弱レーンは自分の velocity 帯を持つので、
  profile 値は純粋に「鳴る確率」になる。「毎回鳴るが小さい打点」は「弱レーンの確率1.0」と書ける
- **密度制約の定義がそのまま実装になる**。「はっきり鳴るハットの数」＝ 強ハットレーンの打点数
- **音色を差し替える崩しが配置の問題に還元される**。「4小節目のスネアだけリムショット」は
  スネアレーンから打点を消してリムショットレーンに置くだけ。崩しの手段が「足す・抜く・強弱・
  音色差し替え」の4種類ではなく、全部**「どのレーンのどこに打点を置くか」の1種類**になる

**トラック構成はレーン別**（`SamplerEngine` は1トラック1サンプルなので必然）。8レーン程度まで許容する。
副次的な利点が2つある。

- **レーンごとにFXを掛けられる**。LaLa のFXチェーンはトラック単位なので、1トラックの Drum Kit では
  キックとハットに別のEQを掛けられない。両者は帯域が真逆（50〜100Hz と 6〜10kHz）なので、
  同じEQで済ませることは原理的にない
- **セクションごとの抜き差しがリージョンの有無で書ける**。バースでハットだけ抜くのが
  「ハットトラックのリージョンを消す」で済む（1トラックだとピアノロールでノートを消すしかない）。
  フック用に1つ振ってバースはレーンを抜く、が抜き差しの基本形になり、
  上記の操作モデル（レーンに打点を置くか置かないか）と同じもので済む

### レーンは絞らない（2026-08-22 決着）

当初は「8レーン常設」とし、何を8つにするかを調べる予定だった。動機は
「ガチャが提案できる崩しは存在するレーンの範囲に限られる」から。だが枠を設けたのは
実装の都合であって音楽的な理由ではなく、**枠を外すと問いごと消える**。

**キットは全カテゴリのサンプルを1本ずつ持ち、トラックは候補が実際に使うものだけ立てる。**
ガチャがクラップ入りの候補を出したときだけクラップトラックができる。画面は圧迫されず、
提案範囲は全カテゴリに開く。ガチャ→LaLa の取り込みはもともとトラックを作る経路なので、
追加の仕組みも要らない。

決め手は本人の言葉:「たまに提案してきたら、大体のものが嬉しい気はする」。
つまり判断は**常に鳴らすか**ではなく**選択肢として持つか**で、後者なら絞る理由がない。
どのカテゴリをどれくらいの頻度で提案するかは、机上でなく使いながら決める。

毎回使うのはキック / スネア / ハット強 / ハット弱 の4レーン。残りは候補として定義だけ持つ。

### ゴーストを持つのはどのレーンか

強/弱で2本持つのはハットだけではない。一般形は**「ゴーストを使うレーンだけ強/弱の2本を持つ」**。

- **ハット = 強/弱**（確定）。境界が「はっきり鳴るハットの数」で決まる以上、密度を足す
  唯一の安全な手段が音量を落とすことで、そのために弱打専用のサンプルが要る
- **スネア = 強/弱**（候補）。ゴーストスネアは生ドラムのグルーヴの骨格で、boom bap は
  ブレイクをサンプリングした音楽なので元ネタに入っていることが多い。ただし基準パターンは
  2拍4拍だけの素朴な形なので、毎回使うレーンではなく候補に置く
- **キック = 1本**。弱打は「知った上で持たない」。**低域は音量を落とすと「小さいキック」でなく
  「聞こえないキック」になる** — 倍音が少ないので、音量が下がると輪郭ごと消える。ハットが
  小さくても存在を保てるのは高域でアタックの立ち上がりが残るから。生ドラムには弱いキックの
  打ち方があるが、打ち込みの hiphop ではまず使わない

## 音色は「組んで比べる」で決める

- **単体試聴で選ばない**（[reference-beat.md](reference-beat.md) の原則。音色の良し悪しは半分以上が
  他パートとの帯域分担で決まる）。パックから適当に1本ずつ選んで基準パターンを組み、
  **リファレンスのドラムステムと A/B** してズレの方向を言葉にし、そこだけ差し替える。
  聴く本数が「差し替えた回数」で済み、ズレが言葉になるので次に買うパックも同時に決まる
- **定番キット ＝ サンプル8本 ＋ レーンごとのFX設定**を固定する。これが reference-beat.md の
  ドラム課題②「少ない労力での調整」の答えになる
- **買う前に手持ちを見る**（2026-08-22）。Logic Pro のサウンドライブラリに
  ワンショットが490本ある（`/Library/Application Support/Logic/Ultrabeat Samples/`。
  `Drum Machine Designer/Crate Digger GB` はこのジャンル向けで、シェイカーまで24本で
  レーン定義をほぼ埋める）。Cymatics 230本と合わせて720本＝量は足りている。
  重心で見ても買い足す根拠は出ていない（Cymatics ×0.83/×0.95/×1.00・Crate Digger
  ×1.11/×1.02/×1.22）。**買う理由になり得るのは重心では測れない質感だけ**
- 調達は Splice のパック単位（サブスクのクレジット制・買い切り不可・解約後も落としたものは残る）。
  **量は reference-beat.md の数字（レーンごと200〜500本）をそのまま読まない** —
  あれは推薦エンジン前提の逆算で、手で選ぶなら**レーンごと10〜20本**で足りる
- 質感差（レコードの上モノ vs クリーンなワンショット）はほぼ確実に起きるが、**先回りして掛けない**。
  浮いたら Lo-fi / サチュで寄せる（[fx-roadmap.md](fx-roadmap.md) のトリガー式のまま）
- 手持ちの Cymatics 230本は捨てて落とし直す方針だが、**「トラップ寄りで方向がズレている」という
  見立ては測定で支持されなかった**（2026-08-22。重心は3レーンとも目標の ±17% 以内。
  [labs](../labs/drum-pattern.md#手持ちのcymaticscobra--eternityとの比較)）。捨てるなら
  「無料DLで選んでいないから」が理由で、方向のズレが理由ではない

### 差の主因はサンプルだった（2026-08-22 の3段比較）

「リファレンスとの差はサンプルか処理か」を、リファレンスから切り出した単発で自分のパターンを
鳴らして確かめた（段1=自分のキット / 段2=リファレンス由来の単発・処理なし / 段3=リファレンス本体）。
**3本中2本で段2が段3側に寄った** → 主因はサンプル。1本は中間だったので処理もゼロではない。
段2にはアーティファクトが残っていた（切り出しで痩せる・同じ1発の繰り返し）ので、
**ハンデ込みで寄った**ぶん結論は補強される。根拠と限界は
[labs](../labs/drum-pattern.md#差は音色か処理か2026-08-223段の比較)。

→ **素材の調達には意味がある。** ただし素材だけで全部埋まるとは思わないこと。

### 音量の揃え方は LUFS（K特性）で

比較素材を作るときRMSで揃えると**低域に偏った素材が小さく聞こえる**（実測で踏んだ）。
ITU-R BS.1770 の K特性で揃える（`kittarget.loudness_lufs`）。ドラムの比較は帯域の偏りが
素材ごとに大きいので、ここを間違えると比較そのものが成立しない。

**実効音量は同じカテゴリ内でも揃っていない**（2026-08-22 実測・Cymatics Cobra）。ピークは
正規化されているが RMS は揃わない — クローズハット13本で −29.8〜−20.6dB の 9.2dB 幅、
パーカは21dB幅。9dB はゴーストの基準にした −12dB と同オーダーで、「はっきり鳴る/鳴らない」を
跨ぐのに十分。さらに減衰時間が効く（クローズハット 0.05秒に対してオープンハット 0.33秒）。
**生成器は MIDI しか吐かないので「はっきり度」を正確に扱えない。**

## 決めていないこと

- **崩しの「距離」の定義**。velocity の合計で測る案は、velocity がサンプルに対する相対値でしかない
  （実効音量はサンプル依存）ため保留。音色がこれから入れ替わるので今決めても検証できない
- ~~音色差の吸収先~~ → **2026-08-22 決着: レーンのゲインで吸収する**。ただし固定ゲインではなく
  **キットを差し替えるたびに解き直す** — レーンを単独でレンダリングして帯域RMSを測り、
  目標のバランス（キック基準で snare −7.0dB / hat −22.7dB）になるゲインを求める
  （`tools/drumlab/kitcompare.py` の `solve_gains`）。ピーク正規化＋固定ゲインでは
  サンプルのエネルギー差でバランスが崩れる。生成器（MIDI側）は音色を知らないままでよい
- 新しいFXの要否（トランジェントシェイパー等）。キットが組めてから

## 生成器で実装しないもの

- 「はっきり鳴っているか」を**合成音から機械で測って**制約するのは不可能。合成ハットは−27dBまで
  下げても onset として検出され続ける（無音の背景に鋭いノイズが置かれるだけで、実曲のように
  他の音の余韻へ埋もれない）。制約は測定でなく**生成側のレーン分けで担保する**
- タイプ切替UI。境界は連続量なので閾値で切らない

## 制約にしないもの

- **ハットの譜割り（8分か16分か）**。実時間の打点数が効くので、譜面上の細かさは条件にならない
- **ゴーストの有無**。上記のとおり肯定側にも音量差ゼロの曲がある
- **ドラム音響・音色**。今回の聴取は「音色でなくパターンで判断」と明示して行っている
  （音色の選び方は上記「音色は『組んで比べる』で決める」。パターンの好みの境界としては条件にしない、という意味）
- **キックの密度・等間隔性**。下の節のとおり境界にならない

## キックは制約にしない（2026-08-22 検証済み）

当初の仮説の前半「キックとスネアが交互だったり等間隔に近い感じで淡々」も検証したが、
**境界にならなかった**。

- **実曲では分離しない**。キック打点/秒は否定 1.09–2.17 に対し肯定 0.95–3.17 で重なり、
  向きも逆（肯定側の上位のほうが密）
- **A/B（密度×等間隔性の2×2）では順位はつくが、全部が許容範囲**。
  本人の判定は「無理とか嫌いとかはどれもない」。ハットで出た質的な差がない
- 順位には交互作用があり（等間隔は疎なら良く密なら悪い）、単一の軸では表現できない

**ドラムガチャのキック profile は現状のままでよい。** 生成器に足すのはハットの制約だけ。

「密かつ等間隔」（キック6打点が8分で完全に均等）。後者はハットの
「均一な音量で細かく刻み続ける」と同じ構造なので、**帯域を問わず
「均一な打点が高密度で並ぶ」のが嫌われる**可能性はあるが、観察1つからの仮説どまり。
