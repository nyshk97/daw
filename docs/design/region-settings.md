# リージョン設定UIの方針 — 常設パネルは作らない

2026-07-24 の壁打ちで確定。Logicの「リージョンインスペクタ」（左パネル最上段の数値リスト）に相当するUIをLaLaがどう持つかの設計判断。

## 結論

**リージョン設定の常設パネル（インスペクタ）は作らない。** 各項目を「リージョン自身に痕跡が見える」形に設計することで、数値の表示場所そのものを不要にする。

## 判断の核: 可視性の原則

Logicのリージョンインスペクタに数値表示が必要なのは、パラメータが**非破壊の再生時オフセット**（トランスポーズ+2やクオンタイズ1/16がリージョンの見た目に痕跡を残さない）だから。逆に言うと:

> **痕跡が見えるように作った項目は、表示場所が要らない。**

- 非破壊オフセットにする → どこかに数値表示が必須になる（＝パネルを要求する）
- 見える操作・見える描画にする → パネル不要

Logicの配置（リージョン設定がトラック設定の上に縦積み）への違和感の正体は、スコープの違うものが同じパネルに同居する汎用DAWの構造で、LaLaは「インスペクタ」概念自体を輸入しない。

## 項目ごとの割り当て

| 項目 | 方式 | 見え方 |
|---|---|---|
| ミュート | 実装済み | リージョンの減光表示 |
| フェードイン/アウト | **実装済み**（2026-07-26）: リージョン上辺の左右のドラッグハンドル（**選択中のみ**表示・10×14px） | 斜線を引き、線より上を暗く落とす（Logic流）。斜線は未選択でも描く。数値表示なし（ドラッグ中ポップアップのみ・ms表示、音量ドラッグと同じ流儀） |
| リージョンゲイン（オーディオ専用） | **実装済み**（2026-07-26）: 右クリック →「ゲイン…」→ CallOutBoxのスライダー（±12dB・`GainScale`共通） | 波形の描画振幅をゲイン込みでスケール＋0dB以外のとき右上にdBバッジ |
| トランスポーズ（MIDI） | ピアノロール上の**破壊的操作**（ノートを実際に動かす） | ノート位置に痕跡が残る |
| クオンタイズ（MIDI） | **破壊的操作**（実行時にstartPpqを書き換え、戻すのはundo） | 同上。マウス入力はスナップ済みなので出番はリアルタイム録音導入後 |
| トランスポーズ（オーディオ） | 非破壊パラメータ（下記） | 0以外のときだけリージョン隅に `+2` バッジ |

「デフォルトは沈黙、逸脱だけ主張」— 常時ゼロ表示が並ぶパネルより、リージョン自身が状態を語る（ミュート減光と同じ文法）。

## オーディオトランスポーズの設計

唯一「見えない数値」が残る項目であり、唯一**非破壊にすべき**項目。

- **用途**: 外部から取り込んだ素材のキー変更（リファレンス楽曲・購入ビートで自分が歌いやすいキーを探る）。自分で録る素材には使わない
- **非破壊にする理由**: キー探りは「+1→+2→やっぱり-1」と往復するワークフロー。破壊的上書きは劣化が累積する。劣化回避には「常に元音源からnetの半音数でシフト」が必要で、それは元バッファ＋transpose値の保持＝実質非破壊
- **再生方式**: transpose値の変更時に裏でシフト済みバッファを生成してキャッシュ→再生はキャッシュを読む。オーディオスレッドにDSPコストを載せず、品質重視の遅いアルゴリズムを使える
- **DSPは自作しない**: 第一候補 signalsmith-stretch（MIT・ヘッダオンリー）、次点 SoundTouch（LGPL・軽量だが品質は中）
- 単位は半音のみ（ファインチューン/セントは需要が出るまで持たない）

## 見送り

- **オーディオクオンタイズ（Flex Time / Elastic Audio 相当）**: トランジェント検出＋高品質タイムストレッチの大物2つを背負う機能で、本命用途は生ドラム。ボーカルのタイミング直しは「⌘Tで切ってリージョンをずらす」で足りるため**永久に不要**
- **MIDIクオンタイズの非破壊版**（グリッドを変えながら試行錯誤する方式）: 表示場所を要求する。破壊的操作＋undoで十分

## 未決（実装スライス着手時にdigで詰める）

- トランスポーズをいじる具体操作（ゲインと同じ吹き出しに同居させるか、別操作にするか。同居させるなら「一時的な吹き出し」が2項目で打ち止めであることを守る＝常設インスペクタに育てない）
- トランスポーズのレンダーキャッシュの保存方式（project.jsonにはtranspose値のみ記録し、キャッシュは起動時再生成か、WAVとして永続化か）

## 決まったこと（リージョンゲイン・2026-07-26）

- **操作**: 右クリック →「ゲイン…」→ `CallOutBox` の横スライダー。メニュー項目には0dB以外のとき現在値を併記する
  - メニューへの直接埋め込み（`PopupMenu::addCustomItem`）は見送り: スライダー幅がメニュー内で他項目の文字幅に引き伸ばされて解像度を制御できず、メニューがリージョンを覆って波形の変化が見えない
  - ショートカットは付けていない（右クリックで足りるか使ってから判断する）
- **見え方**: 波形の描画振幅にゲインを掛ける＋0dB以外のとき本体右上にdBバッジ。バッジは表示名（左上）とループハンドル（右下）を避けた位置で、幅56px未満のリージョンでは出さない
- **スケール**: サンプル音源のGAINと共通（`GainScale` = ±12dB・0dB吸着・`GainControls.h` のスライダーと値ラベルを共有）
- **ドラッグ中も音に反映する**: 通常の `pushSnapshot()` は鳴っているMIDIを消音＋再発音させるため、スナップショットに「MIDI構成の世代」を持たせ、オーディオ値だけの差し替えでは据え置く経路（`Project::SnapshotChange::audioValuesOnly`）を用意した。undoも専用種別（`UndoStack::EditKind::clipValue`）で同じ経路を通る

## 決まったこと（フェードイン/アウト・2026-07-26）

- **操作**: リージョン**上辺**の左右のドラッグハンドル（フェード終端に追従）。ヒット領域は **10px幅 × 14px高**（見えている部分は上辺の8px）で、モックを実マウスでドラッグして決めた（合成クリックは座標を正確に狙えるため操作性を検証できない）
  - **表示条件は「選択中のみ」**。ループハンドルと完全に同じ規則で、レーンにホバー検知を新設せずに済み、未選択アイテムを掴もうとして誤ってフェードが伸びる事故も起きない（1クリック目は必ず選択になる）
  - 斜線（フェードの痕跡）は**未選択でも描く**
  - 判定順は フェードハンドル（上辺）→ ループハンドル（下辺）→ 移動。連なり全体の幅が40px未満ならハンドルを出さない
  - **ハンドルが重なったとき**（`fadeIn + fadeOut` が全長に近い）は**クリック位置に近い方・等距離ならフェードイン**。固定順だと片方が永久に掴めなくなる
- **カーブはリニアのみ**（Logicのデフォルト curve=0 と同じ）。Logicがカーブを可変にしている事実自体が「唯一の正解が無い」証拠で、固定するなら標準値が妥当。実装も `addFromWithRamp` が厳密に一致する
- **掛かる範囲は「ループの連なり全体」の両端だけ**（繰り返しの間はシームレス）。各反復に掛けると繰り返すたびに音量が抜けてポンプする。描画・ハンドル位置も連なり基準（本体rectでクリップすると2反復目以降のフェードアウトが音に掛かるのに画面に出ない）
- **スナップしない**（フェードは平滑化であって音楽的位置ではない）。微調整手段も入れない（精度が要るときは⌘→でズーム。上限640px/小節＝3.1ms/pxなら20〜50msが6〜16pxで引ける）
- **エンベロープは閉区間**（`n-1` で割る＝最終サンプルのゲインが厳密に0）。半開区間だと最終サンプルに `1/n` が残り（240サンプルで-47.6dB）**段差が消え切らない**
- モデル層で不変条件を強制（`Clip::clampFades()`。規則は「fadeIn を先に頭打ち → 残りで fadeOut」）。ただし**フェード自身のドラッグはこの関数を直接通さない** — fadeIn 優先なので相手を押しのけてしまう。`clampedFadeIn/clampedFadeOut` で「相手の手前」に止める
- ループのドラッグ中の再クランプは**ドラッグ開始時の元値**を基準にする（現在値からだと縮めすぎて戻したときにフェードが復元されない）

### 段差と角（実測して整理した）

| 現象 | いつ起きるか | 聴こえ方 | 直し方 |
|---|---|---|---|
| **段差**（値の不連続） | リージョン端が波形の途中の値のまま無音に接したとき | はっきり「プチッ」。素材を問わない | フェードを入れる（リニアで十分。数msで消える） |
| **角**（傾きの不連続） | リニアのフェードの開始点・終了点。短いほど強い | ごく僅かな「コツ」。5ms以下＋低音のときだけ | 手で引くフェード長（20ms以上）では**対処不要** |

- 段差は `-6dB/oct`、角は `-12dB/oct` で減衰する＝**桁違いに弱い**。手で引くフェードでリニアを選ぶ判断に影響しない
- **⌘Tで分割しただけでは、どちらも起きない**（左右が隙間なく連続再生されて元の波形を再現する）。片方を動かした瞬間に、露出した端が段差になる
- **クリック除去の自動化（全境界に固定5ms等）は入れない**: ⌘Tで切っただけの本来シームレスな継ぎ目に10msのくぼみを新たに作ってしまい（ロングトーンを切ると漏れる）、既存プロジェクトの出力も全部変わる

### 曲末フェードとオートメーション（作らない理由）

曲末フェードは**リージョンのフェードで賄う**（他DAWの標準手段はマスターのボリュームオートメーションだが、LaLaはオートメーションを持たない方針）。曲末に残るリージョンは通常ビート1本（＋アドリブ程度）なので個別に掛けて実用上揃う。

オートメーションを入れると、音量の出どころが「フェーダー（手）」と「カーブ（再生ヘッド）」の**2つ**になり、どちらが勝つかを人間が管理する必要が出る。全DAWが **Read / Touch / Latch / Write / Off** のモードをユーザーに選ばせているのはそのため。そして「曲全体を1dB上げたい」の正解はこの5つのどれでもなく「カーブ全体の平行移動」なので、さらに **Trim / Relative** が足される＝**1本のフェーダーの裏に3つの数字**がいる状態になる。

このコストは**恒常的ではなく休眠型**である点が重要。カーブを1本も引いていなければ Read は素のフェーダーと同じに振る舞うので普段は何も見えないが、一度引くと「フェーダーが効かない」が予告なく起き、診断には5モード＋Trimというモデル全体の理解が要る。使用頻度が「1曲に1回」であることを考えると、**不意打ちの深さに対して見返りが小さい**。波及して壊れるものも大きい（データの流れが双方向になる・undoの粒度が別ルールになる・リージョンゲインと役割がかぶる・行の高さが可変になり `row = e.y / trackHeight` 型の計算が33か所ある）。

**判断基準として「オートメーションでしかできない用途が3つ溜まったら作る」を置いた。** 同じ議論を繰り返さないための線引きで、現在は1つ（曲末フェード＝リージョンフェードで代替済み）。
