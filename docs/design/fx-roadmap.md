# FX・メーター実装ロードマップ（バッチ格子）

2026-08-16 の相談で確定。EQ・Comp 完成後の残りFX・メーター群をバッチで実装する。
**この格子は粗い骨格のみ**。各バッチの仕様は着手時に `/dig`（論点が少なければ省略）→ `/plot` で詰め、1実装 = 1 plan として `docs/plans/` に落とす。バッチ完了時にここのチェックボックスを更新する。

**曲作りの再開ラインはバッチ4完了**（2026-08-16 確定）。バッチ5は再開後に「実際に困った順」で着手する — 中身の取捨（トランジェントシェイパーかゲートか等）は使用実感が一番安い判定材料なので、再開前に決めない。

[mixer-fx.md](mixer-fx.md) の6スライス計画のうち、未着手だったスライス5（Reverb+Delay+Limiter）はバッチ2・4に再編。スライス6（外部AU）はこのロードマップの対象外（据え置き）。

## 方針: 正しさの検証と耳の学習を分離する

- **正しさ（動作確認）は機械で検証する**: FFTで倍音次数・実測ゲイン一致・ffmpeg等のリファレンス実装との数値照合・出力天井のテスト。EQ plan の合格基準（解析応答と実測ゲインの一致）と同じ流儀
- **耳は「どう聴こえるか・いつ使うか」の学習**であって品質ゲートではない。バッチごとに耳テーマが揃うよう構成してあるので、バッチ完了後にまとめて「耳セッション」をやる（細切れにしない）
- メーターを先に持つのはこのため: ラウドネスバイアス（大きい方が良く聴こえる）をLUFSで潰せると、以降の全FXのA/B比較が成立する
- 耳セッションの形式は未定。最初のバッチ完了時に設計する（機械的な作業にしすぎない）。ドラムはリファレンスのドラムステムとのA/Bを使う（[reference-beat.md](reference-beat.md) の役割分担の節）

## 順序の拘束（何が固定で何が入替可能か）

- **固定: バッチ1 → 最初の新トラックFX（サチュレーション）**。6経路集約の前に新FXを足すと、コピー箇所と事故リスク（GOTCHAS.md の掛け算位置ズレ）が増えるだけ
- **固定: サチュレーション → Lo-fi**。FxBase の型を3例目で作ってから量産する
- **入替可能: バッチ2 ⇄ 3**。メーター先行は「以降の耳セッションを助ける」ためであって技術的依存ではない。モチベーション次第で前後してよい
- バッチ5は再開後のトリガー式なので順序拘束の対象外

## 削った候補と理由

- **フィルター（独立FX）**: 静的フィルターはEQと重複（LPが欲しければEQ拡張かLo-fiに内包）。スイープはオートメーションがある世界の道具で、LaLaはオートメーションを持たない方針なので居場所がない
- **Chorus**（2026-08-16 確定）: ラップのダブリングは実録テイクで作る文化で出番が薄い。欲しくなったらディレイ基盤（バッチ4）＋トラックFXの型（バッチ3）で後から安く足せる。「知った上で捨てる」枠
- **ドラム合成エンジン**: 合成が成立する領域だが「知った上で選ばない」（音色はサンプル選び主軸・ファイルで持つ。[reference-beat.md](reference-beat.md) の音色調達の節）
- **参照曲比較メーター**: LUFS・スペクトラムが揃い、リファレンスが数曲溜まってから。比較対象データの持ち方が referenceパイプラインの設計に依存するため [reference-beat.md](reference-beat.md) 側のフェーズに寄せる
