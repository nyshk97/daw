# オーディオファイルのインポート＋ステレオクリップ対応

## 概要・やりたいこと

購入ビート・リファレンス楽曲・サンプル素材などの外部オーディオファイル（WAV/AIFF/FLAC/MP3/M4A）をタイムラインに取り込めるようにする。取り込み素材はステレオ2ミックスが普通なので、あわせてオーディオクリップのステレオ再生に対応する。

- 「ビートを貼ってその上にボーカルを録る」フローを完成させるのが主目的
- オーディオトランスポーズ（キー変更）は**次スライス**。本スライスの上に載る（依存は一方向。`docs/design/region-settings.md` 参照）
- ステレオ**録音**はやらない（ボーカルマイク録りはモノが正解）

## 前提・わかっていること

/dig（2026-07-24）での決定事項:

**取り込みの入口**
- 導線は Finder からの D&D＋File メニュー「オーディオを読み込む…」の両方
- D&D: 既存オーディオトラック上＝ドロップ位置（リージョン移動と同じ最小グリッドにスナップ）。トラック下の空白＝新規オーディオトラックを自動作成して配置
- メニュー: 常に新規トラックを作って小節1に配置
- 複数ファイル同時ドロップは先頭の1ファイルのみ処理（自動クローズ通知で知らせる）
- 対応形式は `registerBasicFormats`＋mac の CoreAudio が読めるもの（WAV/AIFF/FLAC/MP3/M4A）

**データの持ち方**
- 取り込み時にデコード＋リサンプルして `clip-NNN.wav`（24bit・プロジェクトSR）へ**変換コピー**。以降は録音クリップと完全に同一の扱い（保存・GC・undo・分割・複製・書き出しがそのまま乗る）
- SR未確定プロジェクト（録音前）への取り込みは**デバイスレートで確定**（現行の「最初の録音時に確定」ルールを「最初の録音または取り込み時」に拡張。`MainComponent.cpp:561` 付近）
- リサンプラーは WindowedSinc（オフラインなので品質優先）
- project.json は v5→v6。Clip に表示名フィールド追加。ch数は JSON に持たず WAV 自体から判定
- モノ録音クリップとステレオ取り込みクリップの同一トラック混在を許す（クリップ単位で ch 数を持つ）

**見た目**
- リージョンラベル: 表示名が入っているクリップ（＝取り込み）だけ左上に小さく描画。録音クリップは無ラベル維持。リネームUIなし。分割・複製で名前引き継ぎ
- 新規トラック名は元ファイル名（拡張子なし）
- 波形は L/R の max を取って1本表示（ピークキャッシュも1本のまま）

**エンジン（コード調査済み）**
- 現状: クリップはモノ前提（`Project::loadWavMono` が ch0 のみ読む・`PlaybackEngine.cpp` の `getReadPointer(0)` 固定）。トラックは「モノ trackScratch に合算 → `Pan::monoGains` で L/R 分配」（`PlaybackEngine.cpp:200-330`）
- 方針: **トラック単位の2経路**。ステレオクリップを1つも含まないトラックは**現行のモノ合算→pan分配コードを素通し**（浮動小数点の演算順序を一切変えない＝既存プロジェクトとビット一致を保証。クリップ単位panへの変形は、重なりクリップの加算順序や send の乗算順序 `(mono×panL)×send` vs `mono×(panL×send)` が変わり一致が崩れるため採らない）。ステレオクリップを含むトラックだけ新経路: trackScratch 2ch にクリップごとpan込みで分配（モノ=`Pan::monoGains`・ステレオ=`Pan::stereoGains`、両法則とも `shared/Pan.h` に実装済み）
- メーター: モノのみトラックは現行の近似（合算ピーク×pan）を維持。ステレオ含みトラックのみ真の L/R 別ピーク
- BounceRenderer のクリップループにも同じ2経路を入れる（再生と書き出しの一致。Pan.h のコメントにある通り両者の出力一致が既存の設計制約）
- バウンス・リージョン書き出しは既に 2ch WAV 出力なので出口は変更不要

**処理の実行**
- BounceRenderer と同じ専用 `juce::Thread` パターンで裏実行（デコード→リサンプル→WAV書き込み→ピークキャッシュ構築）→ 完了時にメッセージスレッドが `undoStack.begin()`＋クリップ/トラック追加。UIはフリーズしない
- 失敗（非対応・破損ファイル）はエラー表示。クリップ/トラック追加は undo 1回で戻る
- undo は既存の構造コピー方式（`UndoStack::begin`）にそのまま乗る。**SR確定は undo 対象外**（UndoStack が戻すのは tracks/markers のみ。録音による確定や音量・ミュートと同じ扱いで、undo してもプロジェクトSRは確定済みのまま。仕様として明文化）
- **排他と原子性**（レビュー指摘で確定）:
  - インポートは**一度に1件**。実行中は D&D・メニューの入口を無効化し「処理中」を通知
  - 変換出力は一時名（例: `import-NNN.wav.partial`。`clip-*.wav` の GC パターンに掛からない名前）へ書き、**完了時にメッセージスレッド上で `nextClipFile()` を引いて最終名へリネーム**（録音完了との clip-NNN 採番競合を構造的に排除。`Project.cpp:610` の nextClipFile は「現在存在しない名前」を返すだけなので予約はできない）
  - 変換途中の保存で `Project::save()` の GC（`Project.cpp:310`）に消されない（一時名が対象外のため）
  - アプリ終了・プロジェクト切替時はキャンセルして join し、一時ファイルを削除
  - 成功時の「モデル反映→undo登録→保存」はメッセージスレッド上の一続きの確定処理として行う

### Phase 2: インポート処理（変換コピーの実体） [AI🤖]

- [x] `AudioImporter`（`audio/` or `shared/`・専用 `juce::Thread`）: リーダー生成（`registerBasicFormats`＋CoreAudio）→ WindowedSinc でプロジェクトSRへリサンプル → 24bit WAV を**一時名**（`clip-*.wav` の GC パターンに掛からない名前）で書き込み → 完了/失敗をメッセージスレッドへコールバック
- [x] リサンプルの仕様を固定:
  - ch の採用: 1ch はモノ、2ch 以上は先頭2chを L/R とする
  - 出力フレーム数 = `llround(inputFrames × targetSR / sourceSR)`（整数丸めで一意に定義）
  - 補間器は**各chで独立に状態保持**（固定ブロックのストリーミング処理で ch 間に状態が混ざらないこと）
  - 入力終端は補間器の lookahead に必要な分をゼロ埋めし、末尾サンプルの欠落を防ぐ（検証は長さだけでなく**音**でも行う: 入力末尾に単発パルスを置き、出力の対応位置付近が無音化・欠落していないことをテストで確認）
  - SR が一致する場合はリサンプルをバイパス（デコードのみ）
- [x] 排他制御: 実行中フラグで**同時1件**に制限。**進捗オーバーレイはモーダルにし、キー操作も消費する**（D&D・メニューの入口無効化だけでなく、ショートカット・他UI経由のトラック削除/並べ替え/編集も塞ぐ。開始時に保持した「対象トラック・配置位置」が完了時まで有効であることをモーダルで保証する。数秒の処理なのでID再解決方式より単純さを優先）。アプリ終了・プロジェクト切替時はキャンセル→join→一時ファイル削除
- [x] SR確定ルールの拡張: プロジェクトSR未確定なら取り込み開始時にデバイスレートで確定（録音側の確定処理と共通化）。**SR確定は undo 対象外**である旨をコードコメントに明記
- [x] 完了時処理（メッセージスレッド上で一続きに実行）: `nextClipFile()` で最終名を確定して一時ファイルをリネーム → `undoStack.begin()` → クリップ生成（表示名=元ファイル名）→（必要なら）新規トラック生成（名前=元ファイル名・拡張子なし）→ スナップショット再push → 保存
- [x] 失敗時のエラー表示（非対応形式・破損・ディスクフル）
- [x] ログ（`shared/Log.h`）: import.start / import.done / import.fail を記録（動作確認の裏取り用）

## ログ

### 試したこと・わかったこと
- 回帰確認は「決定的レンダリングのFNV-1aハッシュをテスト（testMonoRenderRegressionHash）がstdoutへ出力→変更前後で比較」方式にした。変更前の値: hash-engine `59c79a3b0352743f` / hash-bounce `96f5e41dc31e0732`
- BounceRendererのクリップミックスは元からクリップ単位のpan分配（モノ合算ではない）。再生⇄バウンスは元々「数学的同値・ビット非一致」の関係なので、ビット一致保証は「同一レンダラーの変更前後」にのみ適用する
- **WindowedSincは入力100サンプルのアルゴリズム遅延を持つ**（`WindowedSincTraits::algorithmicLatency = 100`）。補償なしだと全体が約2.3ms後ろへずれ末尾が同じ分欠落する——レビュー指摘で追加した末尾パルステストがこれを検出した。AudioImporterは「先頭の遅延分を捨て、その分余計に生成」で補償し、中間パルスの位置ズレ±2サンプル以内をテストで固定
- **実装後レビューで2件修正**: ①Fileメニュー構築（`getMenuForIndex`）への `importAudio` 追加漏れ（コマンド登録だけでは項目は出ない）②リサンプル終端の境界外読み: JUCEの `process(available, wrap)` は **available==0 でも先頭1サンプルを先読みする**（`interpolateImpl` が境界判定より先に `input[numUsed++]` を読む）ため「wrap=0がゼロを供給」に頼れない。ソースバッファ末尾に256サンプルのゼロパディングを確保し、ポインタ・available を常にバッファ実体内（available>=1）に収める方式へ変更

### 方針変更
- 取り込み後の自動スクロール（「追加したリージョンが見える状態にする」）はトラック選択のみに縮小。既存の「トラックを追加」も新規トラックへスクロールしない挙動なので、それに合わせた（D&Dはドロップ位置がそもそも見えている・メニュー取り込みはヘッダーの選択ハイライトで所在が分かる）
- 複数ファイルドロップの通知は専用トーストを作らず、完了表示の文言差し替え（「先頭の1ファイルのみ取り込みました」）で実現（自動クローズ方針を維持しつつ実装最小）
- アプリ実機のGUI検証（メニュー→パネル→取り込み→undo）は、ユーザーが別Spaceのフルスクリーンで作業中（全ウィンドウoffscreen・activateはSpace切替事故のリスク）のため中止し、人間確認へ委譲。代わりに一時ファイルのGC安全性・変換仕様はユニットテストで固定した。選択画面のスクショ確認（別Space撮影）で新バイナリの起動・v5手書きproject.jsonの読込は裏取り済み
