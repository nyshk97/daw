# ステム分離モデル選定ラボ — demucs vs BS-RoFormer SW

## 概要・やりたいこと

Salvaのステム分離で使うモデルを、「自分で作れる最高品質」の基準で選定する。既存資産（demucs）を理由に確定させず、現時点の最上位候補と実素材・実マシンで比較して決める。

**SalvaとreferenceパイプラインはKPIが別なので、採用判定も別に行う**:

- **Salva採用モデル**（このplanの主目的）: 「耳で使える分離音」が基準。ブラインド試聴で決める
- **reference-beat採用モデル**（副次判定）: 「下流分析が正しくなるステム」が基準。既存設計はベース・ドラム=4分割/上モノ=6分割を意図的に使い分けており（reference-beat.md「ステム分離は4分割と6分割の両方を走らせる」）、耳の勝敗では更新しない。グルーヴ位置・ベース音高・コード骨格/ループ長・ゲート通過状況を**人間確認済みの正解と照合**して初めて序列を動かす（BPM等、元音源だけから算出される項目は対象外 — 詳細はPhase 3.5）
- 結論が「SalvaはSW、分析は現行demucs併用」に割れてよい。reference側の回帰比較は本ラボの出力を流用した別判定とし、材料が揃わなければ「未判定のまま現行維持」で終えてよい

- Salva側は `separate.sh` の契約でモデル非依存にしてあるため、ラボの結論は主にスクリプト差し替えで反映できる（Salva実装をブロックしない。着手はSalva先行と決定済み）。ただし**venvとキャッシュの2点は差し替えだけでは済まない**（Phase 4に明記）
- 結果は `docs/labs/reference-beat.md`（追記専用）へ記録する。`docs/design/reference-beat.md` のモデル序列は**reference側の回帰比較が済んだ範囲だけ**更新する

## 判定基準（試聴前に固定）

**比較・採点の単位は「候補モデル」ではなく「Salvaのステムグループ」**（4 STEMS枠 / 6 STEMS枠）。候補ごとに出力グループ数が違う（現行demucsと多段=2グループ、SW単発=6ステム1グループ）ため、モデル単位で比べると4ステム枠にpiano/guitarが無く主評価軸を採点できず、SWだけ1出力で不利になる。

- **4 STEMS枠の候補**: 現行 `htdemucs` vs 多段の4ステム側。主評価軸は vocals⇄other 間の漏れ
- **6 STEMS枠の候補**: 現行 `htdemucs_6s` vs SW単発 vs 多段の6ステム側。主評価軸は上モノ（piano/guitar）への滲み
- **部分採用を許す**（例: 「4ステムはdemucs維持・6ステムはSW」）。拒否条件・採用条件は以下をグループごとに適用する

試聴後に重みが動かないよう、役割を先に分ける:

- **速度・ピークメモリ = 許容上限**（採用条件ではない）: 1曲あたり実測5分以内・実行中に他作業が破綻しない範囲。上限内なら速いことは加点しない
- **耳の結果 = 採用条件**。採点尺度は事前固定: **-2 悪い / -1 少し悪い / 0 同等 / +1 少し良い / +2 良い**（現行demucs比）
  - **採点行の単位**: 曲×区間×対象ステム×軸。対象ステムは4枠=vocals/other、6枠=piano/guitar/other（再加算軸はステム無しで曲×区間×軸）
  - **拒否条件（1つでも該当したらそのグループでは不採用。他が全部良くても覆らない）**: 「本来の音の欠落」「金属的な揺れ・水中感」「アタックの崩れ」「再加算時の原曲との差」の4軸で、**個別行に -2 が1つでも付いた時点で発動**（曲内集約で薄めない — 明確な悪化がどこかで聴こえること自体が致命のため）
  - **曲内集約**: 主評価軸（グループ別定義）について、その曲の対象行（区間×ステム）の**中央値**をその曲のスコアとする
  - **採用条件**: 曲スコアが**曲単位の過半数（2曲なら2曲、3曲なら2曲）で +1 以上**、かつ全採点行の合計が非負
  - **N/A行の扱い**: activity判定（Phase 2）で採点不能とされた行は N/A とし、曲内集約の中央値・全行合計の**分母から除外**する
- 同点・条件未達なら現行demucs維持（移行コストを払う理由がない）

## 前提・わかっていること

- 既存: `tools/reference/` パイプラインで demucs（htdemucs＋htdemucs_6s）が本番稼働中。M系GPUで2モデル計約50秒/曲（reference-beat.md 記載）
- 調査済みの序列（reference-beat.md 2026-08-14）: 現行demucs ≒ 商用中位〜上位、最上位はBS-RoFormer系（重み公開・無料）で差はSDR 1〜2dB。品質はモデル差より**素材の薄さ**の方が効く
- Web裏取り（2026-08-14）:
  - **BS-RoFormer SW**: 6ステム（vocals/drums/bass/guitar/piano/other）、2026年2月時点で6分割の最上位と目される。重み約700MB公開。`bs-roformer-infer`（pip・初回自動DL）または `audio-separator` で実行可。ONNX版・GGUF版の配布もあり
  - 多段（RoFormerでボーカル/伴奏→demucsで伴奏をばらす）はコミュニティ（UVR/MVSEP）の標準手法
  - demucs単体6分割はボーカル滲みが4分割より多い、が通説
- 未知数: **Apple Siliconでの推論速度**（RoFormer系はdemucsより重い）・実素材での耳の差
- 耳確認など再取得できない人間判断は `docs/labs/reference-beat-human-answers/` にコピーを置く運用（既存ルール）

  - モデル名との対応表は**ファイルへ保存**する（`docs/labs/reference-beat-human-answers/<日付>-blind-map.json`。回答完了まで人間は開かない運用。AI側の記憶だけだとセッション消失で人間判断が再取得になる）。開示は**回答完了後**
