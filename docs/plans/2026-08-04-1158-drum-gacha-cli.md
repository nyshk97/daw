# ドラムだけの最小ガチャCLI（Phase 2 の入口）

## 概要・やりたいこと

[reference-beat.md](../design/reference-beat.md) の Phase 2「MIDI生成ガチャ（CLIで完結。LaLaを触らずMIDIファイルの耳チェックで評価）」の最初の一歩として、**ドラム1パートだけ**を制約カード（card.json）から生成する CLI を作る。

- 目的は「制約カード → ルールベース生成 → 耳で選ぶ」のループが**楽しく回るか**を最小コストで実地判定すること。生成順「ドラム→ベース→コード」の土台にあたる
- 全自動の一発生成はしない。CLI は候補を並べるだけで、選ぶのは人間（設計の2本柱のとおり）

## 前提・わかっていること

### 決定事項（/dig-lite 2026-08-04）

- **耳チェックは自前合成 wav を同梱**: kick=サイン＋ピッチスイープ、snare=ノイズバースト、hat=短い高域ノイズを numpy/soundfile で合成し、`.mid` と `.wav` を並べて出す。聴きたいのはグルーヴ（位置・強弱・スウィング）であって音色ではないので、帯域が分かれていれば判定できる。Finder の QuickLook 連打で回す（分析側 `listen/` と同じUX）
- **レーン別 seed を最初から**: 全体 seed から kick/snare/hat のレーン seed を決定的に導出し、`--lock kick=1234` のようにレーン単位で固定して他レーンだけ振り直せる。後から足すと過去候補の seed 再現互換が壊れるため初日から入れる
- **検証用の実カードは `~/Music/daw/references/rip-slyme-楽園ベイベー/card.json`**: 分析済み・全ゲート通過（`excluded: []`）。BPM 112.946 / swing 0.482 / drums スライス完全。開発中の回帰は `tools/gacha/tests/fixtures/` に置く生成器専用の固定カードで回す（Phase 1 参照）

### 調査で確認済み

- card.json の drums スライス（真実の源 `tools/reference/card.py`）: `swing_ratio` / `quantize_dev_ms` / `kick_profile_by_beat`（拍単位4値・max=1.0 正規化）/ `snare_profile_by_16th`（16値）/ `hat_profile_by_16th`（16値）＋ `global.bpm`。**ゲート落ちでフィールドが丸ごと省略される**（例: ハット無し曲は swing_ratio と hat_profile が消える）。生成器は「無いなら自分のデフォルト」と解釈する約束
- LaLa には MIDI トラック＋GM 音源（DLSMusicDevice）＋ Drum Kit（channel 10、`GmInstruments.h:23`）が実装済み。**GM ドラムノート（kick=36 / snare=38 / closed hat=42）で出しておけば Phase 3 でそのまま流せる**
- `pretty_midi` / `mido` / `numpy` / `soundfile` は `tools/reference/.venv` に導入済み。生成側の依存は分析側の部分集合なので venv を再利用する（新しい venv は作らない）
- このマシンの `~/Music/daw/references/` には楽園ベイベー1枚のみ（labs の4曲は別マシンの作業）

### 生成の音楽的方針（最小版）

- **1小節パターンを生成し、指定小節数（既定4）繰り返して書き出す**。フィル・バリエーションは入れない（カードのプロファイルが1小節の統計なので、最小版はその範囲で誠実に）
- **プロファイルは「平均オンセット強度」であって出現確率ではない**（`groove.py` の `slot_profile` が明記: 閾値でヒット判定せず連続値のまま出す）。強度0.3のスロットは「毎小節弱く鳴る」のか「3割の小節で強く鳴る」のか区別できないので、生成側で2層に解釈する:
  - **骨格スロット（profile ≥ 0.35）は必ず鳴らす**。0.35 は分析側の `active_16ths` 判定と同じ閾値（`groove.py:202`）で、「パターンの骨格」の線をそのまま借りる
  - **装飾スロット（< 0.35）は profile 値を確率として seed でサンプリング**。ガチャの振れは主にここから出る
  - ベロシティは両層とも profile 値に比例＋seed 由来の微変動
  - kick は拍単位4値なので拍頭のみに置く（16分位置を信用しない、という分析側の判断をそのまま引き継ぐ）
- **スウィング＝8分裏（スロット 2,6,10,14）を `(swing_ratio - 0.5) × 4分音符` だけずらす（符号付き）**。分析側の定義が `ratio = 0.5 + lag/4分音符`（`groove.py:212`）なのでこれが逆変換。0.5=ストレート、0.55 なら 120BPM で +25ms 遅れ、実カードの 0.482 なら**約 -9.6ms 前進**（裏拍が突っ込む）。ハネは「裏拍をどれだけ引きずるか」で、これがビートの「ノリ」の大半を運ぶ
- **`quantize_dev_ms` は「スロット別平均ズレの絶対値の平均」**（`card.py:130`）。半正規分布の平均とみなし、ガウス σ = dev × √(π/2) ≈ 1.25×dev に換算して散らす。±3σ でクリップし、負 tick は 0 にクランプ。**順序逆転の防止はジッター単体でなく、スウィング適用後の最終 tick 列に対して行う**（swing_ratio 0.8 — plausible 範囲内 — では裏拍が16分1.2個ぶん動き、固定された次のスロットを追い越す。レーン内で tick 列の単調性を強制し、違反はクリップ）。楽園ベイベーは11.3msで「打ち込みだが少し揺れる」性格
- **省略フィールドのデフォルト**: swing_ratio→0.5（ストレート）、hat_profile→8分刻み、**snare_profile→2・4拍頭のバックビート（一般的なドラムパターンの最大公約数）**、kick_profile→拍1・3強の基本形、quantize_dev_ms→0。「無い＝生成器の無難な既定」で、壊れた値を食わない
- **デフォルト補完とエラーの線引き**: フィールドの**不在**だけをデフォルト補完する（ゲート落ちの正当な省略）。存在するのに壊れている値 — `card_version != 1`・BPM が 40〜300 の外・プロファイル配列長違い・0〜1 外の値 — は**エラーで停止**する（card.py の検算を通った正規カードでは起きないので、起きたら手編集かバージョン不整合。黙って直すと気づけない）
- 振れ幅（どこまで原曲に忠実で、どこから逸脱させるか）は数値で決めずに**耳で較正する**。密度スケール等のパラメータ化は聴いてから判断（Phase 2 の実験テーマそのもの）

### 置き場・インターフェース

- 新設 `tools/gacha/`（生成は分析と別の営み。card.json を挟んで疎結合）。プロジェクト名の畳語が決まったらリネームする（安い）
- CLI 案: `drums.py <ref-folder|card.json> [--seed N] [--count 8] [--bars 4] [--lock kick=S,snare=S,hat=S] [--out DIR]`
  - 出力先の既定はカードと同じフォルダの `gacha/`（`references/<名前>/gacha/`）
  - **再現の真実は「レーン seed 3つ＋実効設定」**（`--lock` があると全体 seed だけでは再現できず、また bars 違い・別カードを同じ出力先へ出すとレーン seed だけの命名でも衝突する）。よって:
    - レーン seed は全体 seed から **SHA-256 で導出**（Python の `hash()` は `PYTHONHASHSEED` でプロセスごとに変わるため不可）。**32bit・8桁 hex**（4桁十進だと kick/snare ロックで hat だけ回す運用時、約118候補で衝突確率50%になる）
    - ファイル名は `drums-k<kick8>-s<snare8>-h<hat8>-<cfg6>.mid|.wav`。`cfg6` は**「有効な生成入力」だけのハッシュの先頭6桁** — 補完済み drums 実効設定・BPM・bars・wav サンプルレート・生成器バージョンから計算（生成時刻など非決定要素は含めない）。seed が同じでも設定やカードが違えば名前が変わり、上書きしない
    - 併せて候補ごとにサイドカー `*.json` を書く: 全体 seed・3レーン seed・**補完済みの drums 実効設定そのもの**（カードSHAだけではカードが再生成・削除されたとき復元できない）・BPM・bars・wav サンプルレート・生成器バージョン・デフォルト補完したフィールドの一覧・上記 cfg ハッシュ。ファイル名が失われてもここだけで完全再現できる
    - **候補の書き出しは原子的に**: `.mid` と `.wav` を一時ファイルへ出し、検算完了後にリネーム。サイドカー JSON は**最後に書く＝候補完成マーカー**を兼ねる。途中失敗（MIDI 書き出し後・wav 前など）で欠損候補が残っても、次回はサイドカー不在で「不完全」と判定して再生成できる
    - **同名の既存ファイルは黙って上書きしない**。スキップ判定は名前一致だけでなく「3ファイルが揃っている＋サイドカー内の**完全な cfg ハッシュ**が一致」で行う（ファイル名の cfg6 は24bitで同内容の数学的保証にならない）。不完全なら再生成、完全ハッシュ不一致（短縮ハッシュ衝突）ならエラー。スキップ・再生成は stdout に申告する
  - `--seed` 省略時は OS エントロピー（`secrets`）で初期 seed を作って表示する。`--count N` は全体 seed を `seed, seed+1, …` の列にする（レーン導出が SHA なので隣接 seed でも候補は相関しない）
- mise タスク: `gacha:drums`（usage 方式・可変長は `eval "set --"` パターン）、`gacha:test`

### 実カードの置き場についての注記

検証に使う `~/Music/daw/references/` は、design doc の「共有ルートは作らない」（reference-beat.md）と字面上衝突するが、これは **Phase 0 から続くラボ用の暫定置き場**（`analyze-url.sh` の既定 `--dir` もここ）。Phase 3 で LaLa 内から起動する経路が `<プロジェクト>/references/` に落とすようになった時点で整理する。今回はこの暫定のまま進める。

### 方針変更
