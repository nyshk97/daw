# トラックEQのDSP・エディタ実装（FXスライス3）

## 概要・やりたいこと

FXスロットの EQ（現在ガワのみ・`eqEnabled` のON/OFF＋保存だけ実在）に中身を入れる。mixer-fx.md の6スライス中スライス3。

- Logic Channel EQ と同じ「数学的に正しい」クリーンなデジタルEQを作る（biquad / RBJ cookbook 準拠 = `juce::dsp::IIR`）。合格基準は「RBJの設計式どおりの応答を持つ透明なパラメトリックEQ＝係数から計算した解析応答と、実信号を通した実測ゲインが一致する」こと（Logicとの出力一致はフィルタ形式・Qの定義差があり得るため基準にしない）
- スペクトラムアナライザを背景に敷き、「こもってる」という耳の感覚と「250Hzに山」という数値を結びつける（学習のサブ目的に直結）
- UIは ui-principles.md「操作は削る、概念は隠さない」に従う: コントロールは最小、Hz/dB/Qの実単位と標準語彙（ハイパス/ベル/シェルフ）は隠さない

## 前提・わかっていること

### 確定仕様（2026-08-15 の対話で決定）

- **4バンド**: ハイパス ＋ ベル×2 ＋ ハイシェルフ。保存はバンド配列にして将来の増設を安くする
- **ON/OFFはハイパスのみ**（ハイパスには中立状態がない）。ベル/シェルフは0dB＝実質OFF、ダブルクリックで0dBリセット
- **出力ゲインなし**（音量合わせはトラックフェーダー。「大きい＝良い」錯覚を持ち込まない）
- **ステレオ連動のみ**（L/R別・Mid/Sideモードは見送り）
- **傾き選択なし**: ハイパスは12dB/oct固定（biquad 1個の標準傾き・Logicのデフォルトと同じ）。固定値は「12dB/oct」の静的ラベルで見せる
- **操作系**: グラフ上のポイントをドラッグ＋下部に数値表示（Hz/dB/Q）。数値の直接入力は後回し。バンド別の割り当て:
  - HP: 横ドラッグ=周波数・ON/OFFトグルのみ（ゲイン概念なし・Q固定）
  - ベル: 横=周波数・縦=ゲイン・スクロール=Q・ダブルクリック=0dB
  - シェルフ: 横=周波数・縦=ゲイン・ダブルクリック=0dB（Q固定なのでスクロール無効）
- **アナライザ**: EQ通過後の音（=聴いている音）を表示。カーブ実装→アナライザの2段で実装

### 初期値・範囲（Logic準拠）

| バンド | 既定 | 周波数 | 備考 |
|---|---|---|---|
| ハイパス | OFF・80Hz | 20Hz〜1kHz | Q固定0.71（Butterworth＝山も谷もない素直な遮断） |
| ベル1 | 0dB・250Hz・Q1.0 | 20Hz〜20kHz | こもり帯スタート |
| ベル2 | 0dB・3.5kHz・Q1.0 | 20Hz〜20kHz | 抜け帯スタート |
| ハイシェルフ | 0dB・10kHz | 1kHz〜20kHz | Q固定0.71 |

- ゲイン範囲 ±24dB（実用は±6dB程度だがスイープ探索用に広く）、Q範囲 0.1〜10（対数スケール）
- 周波数軸は対数表示（20Hz〜20kHz）。カーブの縦軸±24dB・アナライザは-60〜0dBFSで**目盛りは独立**（カーブ=加工量・アナライザ=信号の実量。Logicも同じ扱い）

### 既存コードの結線先

- `shared/PlaybackSnapshot.h` の `TrackParams`: `eqEnabled` atomic が既在（UI＋保存のみ・音に未結線）。EQバンドパラメータ（enabled / freqHz / gainDb / q）も**個別の lock-free atomic** としてここに足す（UI書込とオーディオ読取が並行するため。Trackモデルとスナップショットが shared_ptr 共有 → 再pushなしで即反映、フェーダーと同じ経路）。バンドtypeは4本固定なので実行時に持たず index で決める。保存・バウンス用には atomic から吸い出す**プレーン値のスナップショット構造**を分けて用意する
- フィルタの実行状態（biquad履歴）はスナップショット再構築を跨いで持続が必要 → `TrackParams` の「オーディオスレッド専用」領域に置く（`peakL/peakR`・`SynthInstance::activeNotes` と同じ流儀）。**この実行状態はリアルタイム再生専用**。バウンスは既存設計（TrackParamsをワーカーへ渡さず開始時点の値をコピー: `BounceRenderer.h:20`・`MainComponent.cpp:1984`）に合わせ、`TrackRender` へEQ設定をプレーン値でスナップショットし、**独立した TrackEq を生成して開始時に履歴を reset** する — 再生スレッドとバウンススレッドが同じIIR履歴を同時更新する競合を構造的に排除する
- **信号経路は単純挿入できない**: 現行はモノ音声がトラックgain込みで合算（`PlaybackEngine.cpp:312`）・ステレオ音声がgain/pan込みで合算（同:396）・MIDIはシンセ出力から直接mix/sendへ加算（同:762）。EQ有効時は音声トラックを**クリップgainまで→EQ→トラックgain/pan→メーター/send/mix**に組み直し、MIDIはシンセ出力直後にEQを通す。RTとバウンスで処理順を一致させる
- **例外（実装で確定）: ステレオ音声トラックのpanはEQの前に掛かる**。panの法則がクリップ種別で異なり（モノ=等パワー・ステレオ=バランス）合算後には分離できないため、クリップ単位のpan分配→EQ→トラックgainの順にする。EQは左右同一係数のLTIなのでチャンネル別スカラーと可換＝出力はEQ→panと同じ（pan操作中の過渡差はフィルタ記憶時間ms程度・アナライザはL/Rパワー平均なのでモノクリップの等パワーpanでは表示不変、ステレオクリップのバランスpanで最大約3dBの変動のみ）。RT・バウンス同順
- **既存経路（高速パス）を使う条件は `!eqEnabled || 全バンド中立` のOR**。中立の定義は「HP無効 かつ ベル2本・シェルフの **target** gainが0dB」に固定する。モノ経路には演算順序のビット一致契約（`PlaybackEngine.cpp:288`）があるため、バイパス時は現行コードパスをそのまま使い既存の回帰結果を維持する。ただし**切替直後は例外** — 2階層のクロスフェードとSmoothedValueの平滑化が**すべて**完了するまでactive経路に留まり、完了後に高速パスへ移る状態遷移にする（途中で移ると平滑化が切れてクリックになる）。またアナライザ表示中はタップ確保のため中立でもactive経路を使う（下記）
- 保存: `shared/Project.cpp` `currentVersion = 14` → **15**。既存の `fx.eq.enabled` に `bands` 配列を追加。v14以前の読込はバンド既定値
- UI: `FxEditorView` のEQスロットクリック → `FxDetailView::setBody()` に載せる（土台は実装済み。body領域 = 幅フル×高さ約224px）
- **undo対象外**にする: UndoStack は「TrackParams を共有したまま持つため、音量・ミュート・ソロはundo対象外（仕様どおり）」の設計。EQも同じ TrackParams 常駐値なので同じ扱いに倒す（フェーダーと粒度が揃う。復元手段はダブルクリックリセット）。⚠️ 2026-08-15対話の途中案「ドラッグ1回=undo1件」からの変更

### 技術方針

- 係数式はRBJ（makeHighPass / makePeakFilter / makeHighShelf）。オーディオスレッドは確保なしの `IIR::ArrayCoefficients` で計算（後述）、UIのカーブ描画は同じ式の係数から `getMagnitudeForFrequencyArray()` を使う（メッセージスレッドなので `Coefficients` オブジェクト可）＝**描画と音が同じ数式**（ズレようがない）
- **ジッパーノイズ対策**: ドラッグ中の係数を生で差し替えるとプチノイズが出る。パラメータを `SmoothedValue` で平滑化し、目標値と乖離がある間だけセグメント頭で係数を再計算する。平滑値は**実処理セグメント長で `skip(segLen)`** して進め、その戻り値から係数を計算する（エンジンは1コールバックを複数セグメントに分割するため、`getNextValue()` を1回だけ呼ぶ方式だと10msの平滑化が数秒かかる）
- **オーディオスレッドでヒープ確保しない**: `IIR::Coefficients::make*()` は内部で毎回 `new` する（`juce_IIRFilter.cpp:352`）ためコールバック内で使わない。係数は確保なしで `std::array` を返す **`IIR::ArrayCoefficients::make*()`**（JUCE 8・`juce_IIRFilter.h:45`）で計算し、既存の係数オブジェクトへ上書きする。フィルタは最初から全バンド2次で初期化し、状態メモリは TrackParams を公開する前（メッセージスレッド）に確保。トラック追加後の初回処理でもコールバック内の prepare/reset による再確保を起こさない
- **ON/OFF切替のクリック対策は2階層のクロスフェード**: boolの切替はSmoothedValueでは防げないため短いクロスフェード（数ms）で平滑化するが、階層を分ける — `eqEnabled` は**チェーン全体**のdry/full-wet、HPのenabledは**HPバンド位置だけ**の入力/HP出力クロスフェード。1本のwet/dryで混ぜると、ベル+6dB中にHPだけOFFしたときフェード中にベルまで一時的に外れる。高速パスへ移れるのは**両階層のフェードと平滑化がすべて完了した後**
- **IIR履歴のreset条件**: ①prepare/サンプルレート変更 ②シーク・再生再開など時間位置の不連続 ③（無音中に処理を止める場合）再可聴化のタイミング。古い履歴が別位置の音に混ざるのを防ぐ。無音時のdenormal対策として `ScopedNoDenormals` または `snapToZero()` を入れる。**②はオーディオトラックのみ**: MIDIトラックのEQ入力（シンセ出力）はシーク・サイクルラップを跨いでも連続（リリース余韻が鳴り続ける実装）なので履歴を保持するのが正しく、リセットすると鳴っている余韻にゼロ状態の過渡（クリック）を注入してしまう
- サンプルレート変更時は係数再計算（`prepareToPlay` 経由）
- 最小位相EQ＝レイテンシゼロ。補償は不要
- アナライザのタップ位置は**EQ直後・フェーダー前に固定**（Logicのプラグイン内アナライザと同じ点。フェーダーを動かしても表示が沈まず、カーブとの対応が崩れない）。高速パスには同じ位置のバッファが無いため、**アナライザ表示中は中立でもactive経路を使う**（ビット一致の完全素通しはアナライザ非表示時の保証とする）。**フェーダー0・ミュート中もタップは継続する**（表示対象トラックはEQ＋タップだけ進め、出力へはゲイン0で混ぜない）
- アナライザのデータ受け渡し: オーディオスレッドは選択中トラックのEQ後L/Rを**単一のAbstractFifo（2chブロック管理・GOTCHAS パターン2）**へ固定長ブロック単位で押し、**各ブロックに世代IDと実際にタップしたtrackIdを添付**する。L/Rを別FIFOにすると読み書きの割り込みで左右の位置がずれ、atomicの世代IDだけではキュー内に残った旧トラックのサンプルを識別できないため。タップの有効化は**EQエディタを開いている間だけ**
- AnalyzerTapのatomic公開順序（GOTCHAS「対になるatomicは中間状態が安全な順序で」と同じ問題）: 対象trackId・enabled・世代は別atomicなので、切替途中に「新世代＋旧trackId」を音声側が読む瞬間があり得る。①UIは対象trackId等を書いてから世代を**release-store** ②音声側は世代を**前後2回acquire-load**し、途中で変わっていたらそのブロックを破棄 ③UIは **(trackId, 世代) の両方**が現在値と一致するブロックだけ採用
- アナライザの数値処理は `shared/SpectrumAnalyzer.h(.cpp)` に分離し、**UIは結果のdBFS配列を描くだけ**にする（dBFS値を決めるのは描画でなく判断ロジック → ui/に書かないルール。daw_testsで固定できる）。担当範囲: Hann窓・FFT（`juce::dsp::FFT`・4096点）・振幅正規化・片側スペクトル補正・L/Rパワー平均（**モノ和にしない** — L/Rに位相差のある音が打ち消され「聴こえているのに表示から消える」誤表示になる）・対数bin集約・-60dB floor・(trackId,世代)照合
- カーブ計算・バンド定義は `shared/`（UIに判断ロジックを書かないルール。daw_tests で応答を固定する）
- バウンス経路（`BounceRenderer`）にも同じEQ処理を**同じ処理順**で通す（掛け忘れると書き出しだけ音が変わる）。実装は上記のとおり独立インスタンス＋プレーン値コピー。**通常バウンスはEQのリングアウトもテールに含める**（EQ有効のオーディオトラックがあれば wantTail を立て、テールで無音入力のままフィルタ履歴が-60dBへ減衰しきるまで書く。サイクル書き出し・曲末フェード・⌘Eは厳密長のまま）
