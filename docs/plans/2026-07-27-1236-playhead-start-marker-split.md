# 再生ヘッドと再生開始位置の分離（停止してもヘッドを置き去りにしない）

## 概要・やりたいこと

現状、Space で停止すると再生ヘッドが即座に「再生を開始した位置」へ戻る（`MainComponent.cpp:718` の `seekRequest.store (playStartSample)`）。このため **聴きながら止めた位置で ⌘T 分割ができない**（⌘V の貼り付け位置・ファイルのインポート位置も同じ問題）。

原因は1本の線が2つの役割を兼ねていること:

1. **今どこを聴いているか** — 編集操作（⌘T / ⌘V / インポート）の基準
2. **次にどこから鳴るか** — 頭出し位置

停止した瞬間にこの2つが食い違うので、役割ごとに印を分ける。Pro Tools の Play Start Marker と同じ考え方（あちらが2概念を持つのは、同じ場所から何度もテイクを録り直すワークフローが主役だから）。

## 前提・わかっていること

### 決定した仕様

- **再生ヘッド**（全高の白線＋ルーラーの三角・現状のまま）＝ 今いる位置。⌘T / ⌘V / インポートの基準
- **再生開始位置**（ルーラー上端の控えめな三角**のみ**。タイムライン本体には線を引かない）＝ 次に再生・録音が始まる場所
- 普段は重なって1本に見え、**再生して止めた瞬間だけ分離する**

| 操作 | ヘッド | 開始位置 |
|---|---|---|
| Space で停止 | 止めた位置に残る | 動かない（＝次はここから鳴る） |
| Space で再生 | 開始位置へ飛んで走る | 動かない |
| ルーラー/タイムラインのクリック | 移動 | 一緒に移動 |
| `,` `.` / セクション移動（`;` `'`） | 移動 | 一緒に移動 |
| **録音開始（`r`）** | **カウントイン開始位置（punchIn の1小節前）へ飛んで走る** | **punchIn（開始位置を小節頭へ丸めた所）に揃う** |
| 録音停止（`r` / Space） | 録り終わった位置に残る | 録音開始小節の頭のまま |

- **タイムラインに線を引かない理由**: 再生中に画面を縦断する線が2本あると「どっちがヘッドか」が一瞬迷う。`docs/design/ui-principles.md` の強弱方針（プレイヘッド＞リージョン＞マーカー）に素直に従う
- **クリックで両方動かす理由**: クリック＝「ここから聴きたい」意図。分割は ⌘T がヘッド基準で動くのでクリック不要＝頭出し位置は勝手には失われない
- **録音が開始位置基準である理由**: 「同じ場所から何度も録り直す」が主用途。Logic は停止でヘッドが戻るので実質「開始位置から録音」、Pro Tools は Play Start Marker から録音で、どちらも結果は同じ
- **「開始位置へ戻す」専用キーは追加しない**: Space で再生すれば自然に解消するため

### 調査で分かったこと

- `playStartSample` は `MainComponent` のメンバ（`MainComponent.h:304`）として**すでに存在**。内部状態の追加は不要で、やることは「停止時に seek し返すのをやめて、代わりに描く」
- 代入箇所は6つ: `MainComponent.cpp:265`（クリックシーク）/ `726`・`737`（再生開始・サイクル頭補正）/ `822`（録音停止）/ `2867`（`,` `.` シーク）/ `2901`（セクション移動）
- **録音開始は再生ヘッドから punchIn を算出している**（`MainComponent.cpp:793-796`）。分離後は「小節1から再生 → 小節5で停止 → `r`」で小節5から録音されてしまい、仕様表と食い違う。Phase 4 で基準を開始位置へ移す
- **録音時のヘッド移動は `PlaybackEngine::startRecording()` が既にやっている**（`PlaybackEngine.cpp:757` で `punchIn - countInSamples` へシーク）。UI 側から punchIn へ追加のシークを書くと、順序次第で**1小節カウントインが消える**。ヘッドの移動はエンジンに任せ、UI は開始位置だけ更新する
- `seekRequest` はオーディオコールバックの先頭で消費される（`PlaybackEngine.cpp:71-73`）。**停止中もコールバックは回り続ける**ので反映は1バッファ分（数ms）だが、編集位置を読む側は `playheadSamplePos` を直接見ている（`TimelineView.cpp:2048`・`2096`、`MainComponent.cpp:3071`・`140`・`2849`、`PianoRollView.cpp:529` の貼り付けと `565` 付近の `playheadRegionPpq()`）ため、原理的に「クリック直後の1バッファ間だけ旧位置で切れる」余地がある。既存の `togglePlay` が `pendingSeek` を見ている（`MainComponent.cpp:724-728`）のはまさにこのレースを避けるためで、同じ考慮を編集位置にも広げる
- 分割のログ名は `region.split`（`TimelineView.cpp:2086`。オーディオクリップ・MIDIリージョン共通）
- `MainComponent` はプロジェクトごとに生成される（`Main.cpp:336`）ので、プロジェクト切り替え時の `playStartSample` リセットは不要
- ルーラーの再生ヘッド描画は `TimelineView.cpp:203-212`（縦線＋下向き三角、`Theme::playhead` = 白）
- 再描画は `TimelineView.cpp:1141-1149` で `lastPaintedPlayhead` によるキャッシュ判定をしている。**停止中はヘッドが動かない＝ここを通らない**ので、開始位置もキャッシュ判定に含めないとマーカーが更新されない
- サイクルON時に範囲外から再生すると開始位置がサイクル頭へ飛ぶ（`MainComponent.cpp:731-738`）。この挙動は維持する（今まで見えなかったジャンプが可視化される副次的な改善になる）
- CTest は `Tests/TestsMain.cpp` の自前 `expect` ベース。純粋ロジック向けで、今回のトランスポート状態遷移を直接テストできる形にはなっていない（回帰確認として実行する）
- ネイティブメニューは File のみ（`Main.cpp:42`）で分割項目はない。JUCE アプリはキー合成が効かないため、⌘T の自己検証は右クリックメニュー（CGEvent 合成）かユーザー操作になる

## 実装計画

### Phase 1: 位置操作を「locate」と「開始位置だけ」に分ける [AI🤖]

操作表の規則をコードの形で固定する。setter 1本だと呼び出し側で `seekRequest.store()` を別に書くことになり、片方だけ書き忘れる余地が残るため。

- [x] `MainComponent` に2つの操作を追加する
  - `locate (samplePos)` — ヘッドと開始位置を**同時に**動かす（`seekRequest.store()` ＋ 開始位置更新 ＋ `timeline` へ通知）
  - `setPlayStart (samplePos)` — 開始位置だけ動かす（録音まわり専用）
- [x] クリックシーク（`265`）・`,` `.` シーク（`2867`）・セクション移動（`2901`）・**サイクル頭補正（`736-738`）** を `locate()` に置き換える（サイクル頭補正は現状すでに開始位置とヘッドの両方を書いており、`locate (cycleStart)` そのもの。ここを落とすと「再生はサイクル頭なのにマーカーだけ旧位置」になる）
- [x] `playStartSample` の宣言に「直接代入せず `locate()` / `setPlayStart()` を使う」コメントを添える
- [x] `TimelineView` に `setPlayStartSample (juce::int64)` と描画用メンバを追加し、値が変わったときだけルーラーを repaint する

### Phase 2: 編集位置の一元取得（保留中シークを含める） [AI🤖]

### Phase 4: 停止・再生・録音の挙動変更 [AI🤖]

- [x] `togglePlay()` の**停止**分岐（`715-721`）から `seekRequest.store (playStartSample)` を削除する。ログは `pos=`（残るヘッド位置）と `startPos=`（次に鳴る位置）の両方を出す
- [x] `togglePlay()` の**再生**分岐（`724-742`）を修正する。**ここが要**: 現状は `playStartSample` をヘッド位置から取り直しているが、分離後は「ヘッドが開始位置と離れた状態から再生する」ケースが常に起きるので、`playStartSample` をそのまま使って `seekRequest.store (playStartSample)` でヘッドを飛ばす（`pendingSeek` を見る必要は Phase 1 の `locate()` により無くなる）
- [x] `startRecordingFlow()`（`793-796`）の punchIn 算出基準をヘッドから**開始位置**へ変える。変更はこの2点だけに留める

- [x] `stopPlaybackForBounce()`（`1731-1742`）からも `seekRequest.store (playStartSample)` を撤去し、再生停止と挙動を揃える
- [x] `,` `.` シークの一時停止→自動再開（`seekResumePending`、`538-556` / `2821-2838`）が分離状態と噛み合うか確認する。シーク中は開始位置とヘッドが一致し続けるはずなので、ズレが出るなら `locate()` 化の漏れを疑う

## ログ

### 試したこと・わかったこと

- 意匠は3案（A: 半透明の小さい三角 / B: 白の輪郭のみ・同サイズ / C: 右向き三角）を実物のルーラーへレンダリングして比較し、**案B**に決定。塗り＝現在地／中抜き＝次に鳴る場所の対比が読み取りやすく、重なると1本に見える
- 1つの `juce::Graphics` に対して `paintEntireComponent` を2回呼ぶと**1回目が描かれない**（上半分が空になった）。ケースごとに別 Image へ描いて `drawImageAt` で積むと解決
- レビュー指摘で判明: `seekRequest.exchange()` で先に要求を消してからヘッドを書くと、「要求なし＋旧ヘッド」の一瞬を UI が読む競合窓が残る。適用手順を `TransportState::applyPendingSeek()` に移し、**先にヘッドを公開してから CAS で自分が読んだ要求だけ消す**順序へ変更した（中間状態が「要求あり＋新位置」になり、どちらを読んでも新位置）。GOTCHAS.md にパターンとして記録
- Phase 5 の実機検証（AXPress＋ログ・合成右クリックでの分割）は**未実施**。起動中の dev インスタンスが旧バイナリ（12:34起動／バイナリは13:11更新）で、ウィンドウタイトルが `● `付き＝未保存変更あり、かつユーザーが在席中（HIDIdleTime=0・Arc操作中）だったため、quit も合成操作も見送った。代わりに `TransportState::uiPositionSample` の単体テストを CTest に追加し、描画はオフスクリーンで確認した
