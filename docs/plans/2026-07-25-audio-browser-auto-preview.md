# オーディオブラウザの試聴を「選択＝即試聴」にする

## 概要・やりたいこと

右パネルのオーディオファイルブラウザで、選んだファイルを気軽に鳴らせるようにする。

現状は「行を選択 → フッター右下の再生ボタンまでマウスを運ぶ → 押す」の3手が毎回必要で、`refreshSelection()` が選択のたびにプレビューを停止するため、別のファイルを聴くたびに同じ往復が発生する。ボタンはリストから最大で縦横数百px離れており、素材を流し聴きする用途に耐えない。

これを次の2点で解消する。

- **A: 選択＝即試聴**（オートプレビュー）— 行を選んだ瞬間に鳴る。↑↓で流し聴きできる
- **B: 行アイコンで再生/停止** — 行左端の `♫` をホバー中は ▶、再生中の行は ■ に変え、クリックで再生/停止

あわせてフッターの再生ボタンを廃止し、UI の総量はむしろ減らす（「引き算」の方針を維持する）。

## 前提・わかっていること

### /dig-lite（2026-07-25）で決定した仕様

| 項目 | 決定内容 |
|---|---|
| オートプレビュー | 行を選択した瞬間に試聴を開始する。↑↓キーでの選択移動でも鳴る |
| デバウンス | 選択確定から 150〜250ms 待ってから開始する（↑↓連打時の連続デコードを抑える。取りこぼしの安全性は `AudioFilePreview` の generation 管理が既に担保している） |
| ON/OFF トグル | **セッション内のみ**。アプリ起動時は常に ON に戻る。設定ファイルへは永続化しない |
| トグルの置き場所 | オーディオブラウザ内・パンくず行の右端にスピーカーアイコン（borderless の `IconButton`） |
| 試聴の出自 | **auto（選択由来）と manual（▶クリック由来）を区別して保持する**。後述の抑止・停止判断はこの出自で分岐する |
| トランスポート走行中 | オートプレビューしない。**走行を開始した時点で auto 由来の予約・loading・playing を停止する**（選択直後に Space を押しても重ならない）。manual 由来の試聴は走行中も継続・開始できる |
| トグル OFF | 予約だけでなく**実行中の auto 由来の試聴も停止する**。manual 由来の試聴は止めない |
| パネルを閉じる / メモへ切替 / 取り込み開始 | **出自を問わず予約・実行中の試聴をすべて畳む**（`cancelAll`）。閉じた後に予約が発火して鳴らないこと |
| 選択が変わったとき | 停止対象が無くても**停止要求を出す**（前回の失敗で出たフッターのエラー表示をここで消すため） |
| 行アイコン | 通常 `♫` / ホバー中の行 ▶ / **試聴対象の行**（loading・playing とも）■。クリックでその行の再生・停止をトグルする |
| フォルダ行 | **従来どおり常に `▸`**。▶ にはならず、クリック領域も設けない（選択・階層移動は今のまま） |
| 試聴対象行の判定 | **選択行ではなく試聴中のファイルパスで判定する**（非選択行の ▶ を押しても表示と実際の音が一致するように） |
| ヒット領域 | アイコンのクリック領域は 24px 以上を確保する（実マウスで狙える幅） |
| フッター | 再生ボタンを廃止し「ファイル名＋長さ＋状態（読み込み中・エラー）」だけに縮小。高さ 78px も詰める |
| 停止手段 | 別の行を選ぶ / 試聴中の行の ■ をクリック / トグルを OFF にする（auto 由来のみ）/ トランスポート開始（auto 由来のみ）。新しいキー割り当ては追加しない |
| 入れないもの | 波形表示・シーク・試聴音量スライダー・キーボードショートカット・設定の永続化 |

### コードベース調査結果

- `AudioFileBrowserView`（229行）が試聴 UI を持つ。`resized()` で最下段 78px をフッターに割き、その右端 64px が `previewButton`。`paint()` の `drawHorizontalLine (getHeight() - 78)` も同じ値に依存している
- `refreshSelection()` が選択のたびに `stopPreviewUi()` ＋ `onPreviewStopRequested()` を呼んでいる。ここが A の差し込み点になる
- `AudioFilePreview` はワーカースレッドでファイル全体をデコードして Snapshot を push する設計。`requestedGeneration` / `playingGeneration` で世代管理されており、新しい `start()` が来れば古い要求は破棄される
- `MainComponent` は `timerCallback` 相当（`MainComponent.cpp:383` 付近）で毎フレーム `setPreviewState()` / `setImporting()` を browser へ push している。トランスポート走行中フラグも同じ経路で渡すのが既存パターンに沿う
- `IconButton::Icon` に `play` / `stop` はあるが**スピーカーが無い**ため追加が必要。線画アイコンは24x24のデザインボックス上で定義する流儀（`design()` / `at()` / `strokeWidth()`）
- アプリ全体設定の永続化機構は**存在しない**（`PropertiesFile` 等の使用ゼロ、ブラウザの初期ディレクトリも毎回 `~/Downloads` 固定）。トグルをセッション内に留める判断はこれと整合する
- **行の D&D（タイムラインへのドラッグ取り込み）と行選択は `ListBox` 内部の行コンポーネントが担っている**。ホバー・クリック検出のために行の mouseDown を奪うと、`getDragSourceDescription()` 経由のドラッグ取り込みが壊れる。ここが今回いちばんの詰まりどころ
- **`refreshComponentForRow()` の行コンポーネントはスクロール時に別の行へ再利用される**。JUCE のドキュメントに «the given row (which may be different from the one that the component was created for)» と明記されている（`juce_ListBox.h:83`）。作成時の行番号をクリックコールバックへキャプチャすると、スクロール後に別ファイルが鳴る
- `daw_tests` は `Tests/TestsMain.cpp` と `audio/` `shared/` の .cpp だけをリンクしており **`ui/` を含まない**（`CMakeLists.txt:212-222`）。ただし `target_include_directories(daw_tests PRIVATE Source)` があるため、判定ロジックを **juce_gui_basics 非依存のヘッダオンリー**にすれば CMake を変更せずテストから include できる

### 試聴状態の管理（`ui/PreviewPolicy.h`・ヘッダオンリー）

auto/manual・予約・トランスポート・トグルが絡んで条件分岐が増えるため、判定だけを juce_gui_basics 非依存の小さなヘッダへ切り出し、`daw_tests` から直接テストする（UI 描画やタイマーは持たせない。汎用化はしない）。

`AudioFilePreview` は**末尾まで再生すると自分で `Status::idle` に戻る**（`AudioFilePreview.cpp:138-140`。オーディオスレッドから `currentStatus.store (Status::idle)`）。UI 側は毎フレームの `setPreviewState (loading, playing, error)` でしかそれを知れないため、**`loading || playing` が false に落ちた時点で `activeFile` を解除する同期**が必須になる。これを怠ると自然終了後も ■ が残り、次のクリックが「停止」と判定されて鳴らなくなる。失敗時も同様に解除するが、**フッターのエラー表示だけは残す**（`statusLabel` は `previewError` を出し続ける既存動作を維持）。

保持する状態は次の4つだけにする。

- `enabled`（トグル）/ `transportRunning`
- `pendingFile` + `pendingSource`（デバウンス予約中のファイルと出自）
- `activeFile` + `activeSource`（loading/playing 中のファイルと出自）

判定として切り出すもの（いずれも「どうすべきか」を返すだけで、副作用は呼び出し側が実行する）。

| 判定 | 期待する結果 |
|---|---|
| 選択が変わった | トグル OFF・走行中・非対応ファイルなら予約しない。それ以外は auto として予約 |
| トランスポートが停止→走行に**遷移**した | auto 由来の予約・実行中を停止する。manual 由来は残す。**走行中フラグが毎tick渡されても遷移時だけ処理する**（繰り返し停止しない） |
| トグルが ON→OFF になった | auto 由来の予約・実行中を停止する。manual 由来は残す |
| 行アイコンが押された | 同じファイルが loading/playing 中なら停止、それ以外は manual として即開始（デバウンスを挟まない） |
| 試聴が idle/failed になった | **自然終了・エラーを問わず `activeFile` / `activeSource` を解除する**。解除前の行を再描画対象として返す |
| 行が ■ 表示か | `activeFile` と一致するか。**loading 中も ■ にする**（デコード中にも停止できるように） |

### 行アイコンのホバー/クリック実装方針

`ListBox` は行ホバーを通知しないため、次の構成を第一候補とする。

1. ホバー行の検出は `listBox.addMouseListener (this, true)`（nested children 込みの**監視**。既存のマウス処理を奪わない）＋ `getRowContainingPosition()`。`mouseExit` と `mouseWheelMove` でホバー解除
2. 描画は現行どおり `paintListBoxItem()` の prefix 差し替え（`♫` / ▶ / ■）で行い、変化した行だけ `listBox.repaintRow()`
3. クリックは `refreshComponentForRow()` で返す**透過の行コンポーネント**（`setInterceptsMouseClicks (false, true)`）の中に、アイコン領域だけを覆う小さな子コンポーネントを置いて受ける。行コンポーネントごとスクロールするので位置追随が自動で効く
4. **行コンポーネントは再利用されるので、`refreshComponentForRow()` が呼ばれるたびに現在の行番号をコンポーネントへ書き直す**。クリック時は「作成時にキャプチャした行番号」ではなく、更新済みの行番号（またはそこから解決したファイルパス）を使う

これで「アイコン以外の場所は従来どおり選択・ドラッグできる」を保ったまま、アイコン上のクリックだけ横取りできる。うまくいかない場合の代替は「ListBox の上にフローティングの ▶ ボタンを1つ置いてホバー行へ移動させる」方式（スクロール追随を自前で書く必要がある）。

アイコンクリックは JUCE の行選択処理を通らないため、**一連の明示的な操作として自前で行う**。

1. デバウンスのタイマー予約をキャンセルする
2. 「選択変更に反応してオート予約しない」ガードを立てる
3. 対象行を選択する（`selectRow()`。フッターのファイル名・長さも追随させる）
4. ガードを外す
5. `PreviewPolicy` の判定に従い、同じファイルが loading/playing なら停止、それ以外は manual として即開始する
6. 状態が変わった行を `repaintRow()` する（旧 ■ の行と新 ■ の行の両方）

ガードを省くと `selectedRowsChanged()` が走って「停止 → 200ms 後にオート再開」となり、手動再生を自分で潰す。
