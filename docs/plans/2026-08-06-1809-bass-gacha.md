# ベースガチャ — ドラムと同時試聴まで（GM音色）

issue: [#2](https://github.com/nyshk97/daw/issues/2) / 設計の親: [docs/design/reference-beat.md](../design/reference-beat.md)「Phase 2 の残りの着手順」

## 概要・やりたいこと

ガチャパネルでベースを振り直し、既存のドラムガチャと同時に試聴できるようにする（音色は GM のまま）。
トラップではキックと 808 が噛み合って 1 つのグルーヴを作るため、ドラム単体では「808 が乗れば正解だったパターン」を落としてしまう——ドラム＋ベースが揃って初めてガチャの評価が当てになる、が動機。

/dig（2026-08-06）で前提が 1 つ更新された: **作る曲のボリュームゾーンはメロディアスな chill 系 hiphop で、トラップはたまに**。chill 系のベースは「進行を運ぶ楽器」（コードループに沿ってルートが動く）なので、トラップの「ルート連打の 808」だけを想定した生成器では初回の実使用で外す。生成はカード駆動で両対応にする（下記）。

この issue で判定すること（issue 本文より）:
- ドラム単体の選別と、ドラム＋ベースでの選別で評価が実際に変わるか
- 制約カード `bass` スライスの統計が生成制約として足りるか

## 前提・わかっていること

### /dig で確定した設計判断

- **プロジェクトに「キー」状態を新設**: project.json に key（root + mode）。常設のキーUIも今回作る（BPM と同格の基本情報として）。生成は常にプロジェクトのキーで行い、カードの `global.key` を生成時に読まない（reference-beat.md の既存決定を守る）
- **キーのコピー導線**: 既存の分析完了ダイアログ（「BPM をプロジェクトに設定」`MainComponent.cpp:2656` 付近）にキーを同乗させる＋ガチャパネル側にも導線。コピー時に**ルートとモードを確認・変更できる**
  - ルート変更 = 声域対応。本人は購入ビート時代、音声ピッチシフトの劣化で ±1音半が限界だった。生成 MIDI ならこの制限が消え「キーが合わないから諦める」分類自体が無くなる
  - モード変更 = キー検出器の平行調取り違え（rau-def-freeze が「C# major」と出ているが実態は B♭ minor の可能性）の保険
- **パネルはパーツ切り替え型**: パネル上部に Drums / Bass のパーツ選択（将来 Keys 等が +1 されるだけ）。候補リスト・カード参照・ロックは**パーツごとに独立** → パーツ別カード参照（ドラムは曲A・ベースは曲B）が成立する。第4レーン統合案は上モノ拡張時にリストの意味が崩れるため不採用
- **仮配置はパーツごとに同時保持**: GachaSession を一般化し、ドラム仮配置のままベースも仮配置 → パーツを行き来して「ベースを聴いてからドラムを振り直す」ができる（issue の判定事項の検証に実質必須）
- **音高はカード駆動**: chords スライスがあれば **loop_bars 分のルート列（進行）をガチャ**、無ければルート固定・1小節に退化
  - ハーモニーグリッドは**半小節**（分析器 topline.py が1小節を2分割している）。カードの chords スライスに `slots_per_bar: 2` を明示的に追加し、ルート列は loop_bars × slots_per_bar スロットで生成する。小節ごと1ルートでは my-way の「8小節・16スロット・14変化」（changes_per_loop=14 > 8）を表現できない
  - chill のリファレンス → chords あり（実測: my-way は loop_bars=8）→ 進行が振れる
  - トラップのリファレンス → chords 欠落 or 動き無し → ルート連打に自然に退化。ジャンルスイッチを生成器に付けず、リファレンス選びがジャンルを決める
  - 副作用として「ベースが進行の骨格を先に決め、上モノガチャが後で和音を付ける」依存になる（実際のビートメイクでも普通の順序で、生成順ドラム→ベース→上モノと整合）
  - コード進行の実物はカードに無い（パクリ回避の既存決定）ので、「性格（loop_bars・root_motion・changes_per_loop）だけ借りて進行はガチャ」になる
- **キック噛み合わせ**: 配置済みドラムリージョンから**実ノート位置を抽出**して bass.py に渡す（seed 渡しでなく。ピアノロールで手直しした・手打ちのドラムにも噛み合う）
  - CLI 契約: **ドラムリージョン先頭基準の相対 PPQ tick 列**。bass.py は自分のパターン長（loop_bars）へ mod で折り畳んで使う。ブースト判定は最近傍16分スロット単位
  - オフグリッド情報の活かし方: **同時打ちとして発音が選ばれたスロットは、ベースノートをキックの実 tick へスナップして置く**（丸め→独自ジッターだと結局ズレて「情報を落とさない」が嘘になる）。それ以外の発音は通常のタイミング処理
  - 参照するドラムの解決順: **仮配置中の Drums リージョン → 選択中の Drum Kit リージョン → 無し**（無ければキックブーストなしで生成する。ベース単独でも振れる）
- **ロック軸は 進行 / リズム の2軸**: ドラムのレーン別 seed と同じ仕組み( 2レーン相当)。「進行は当たり、リズムだけ振る」ができる
- **パターン固有長と試聴長を分離する**: ベースのパターン固有長は loop_bars（1/2/4/8）、ドラムは1小節。リージョンは自動反復されないため、**試聴長 = max(ドラム仮配置長, ベースの loop_bars)** とし、短い側はパターンの繰り返しで試聴長まで埋める（bass.py も drums.py と同じ「パターン×繰り返し」方式。両者とも決定的なので、同一 seed で `--bars` だけ変えた再生成が同じパターンを保証する）。1小節ベース＋4小節ドラムのようなトラップ系の組でも無音区間を作らない
  - **延長再生成できるのは seed を持つガチャ産の仮配置ドラムだけ**。手直し済み・手打ちの既存リージョンが試聴長より短い場合、v1 では延長対象外（そのまま。後半はドラム無しで鳴る。サイクル範囲を短く取れば実用上は回避できる）。一時的な反復リージョンの自動生成はしない
- **CLI 中間チェックポイントを挟む**: bass.py を drums.py と同作法（決定性・sidecar・porcelain・テスト）で先に完成させ、耳チェックは**ドラムと重ねた合成 mix wav** で行う。ルート列生成という新規ロジックのバグを UI 統合前に単体で潰す

### plan 細部（/dig 終盤で宣言済み・異論なし）

- ベース音域は2段構え: **ルート（ルート列）のオクターブ選択窓 = MIDI 28..39 の12半音幅**（どのキーのルートも必ず1箇所に置ける。9音幅だと C♯/D/D♯ が置けない）、**装飾込みの全ノートのハード範囲 = MIDI 28..51**。オクターブ装飾は **+12（上）のみ**許可 — 28..39 内へクランプするとルートに戻って no-op になり、-12 は E1 未満のサブ帯域に沈むため。5度（+7）・ダイアトニック7度（+10/11）も 28..51 に収まる。カードの `pitch_center` は参考値。**表記注意**: MIDI 28..39 は科学的表記で E1〜D♯2、LaLa のピアノロール表示（C3=60 流儀・`PianoRollView.cpp:74`）では **E0〜D♯1**。実装時に12半音ずらさないこと
- **swing・ジッターはベースに適用しない**: bass スライスに swing_ratio は無く、ドラム側の値を借りる経路も作らない。~~タイミングの揺れは quantize_dev_ms のジッターと同時打ちスナップのみ~~ → 実聴レビューで quantize_dev_ms のジッターも廃止（v4）。**タイミングはグリッド正位置＋キック実 tick への同時打ちスナップのみ**（カードの bass.quantize_dev_ms は読まない）
- 装飾音は**スケール構成音のみ**（完全5度・オクターブ・そのモードのダイアトニック7度 = minor なら b7、major なら M7 は使わず5度系に倒す）。クロマチック音は v1 では許可しない
- 自動作成する Bass トラックの GM 音色は **Finger Bass (33)** を既定（ボリュームゾーンが chill。トラック側でいつでも変更可）
- プロファイル解釈はドラムの骨格/装飾2層（0.35閾値）を使わない。実カードのベース `onset_rate_by_16th` は平坦（最大 0.40〜0.83）で閾値が機能しないため、**`notes_per_bar` を目標本数にした重み付きサンプリング**にする
- **モノフォニック**（次ノートで前を切る）・ノート長は `note_length_16ths` 基準
- キー未設定のプロジェクトでベースを振ろうとしたら、キー設定（カードからのコピー）を促す導線を出す
- ドラム振り直し後のベース仮配置は stale 許容（自動再生成しない。気になったら振り直す）
- キーUIの見た目・ベース候補行のミニチュア表示は実装時に **HTMLモック**で方向を確定してから実装する
