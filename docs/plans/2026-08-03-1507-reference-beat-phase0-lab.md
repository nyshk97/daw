# リファレンス駆動ビートメイク Phase 0: 分析ラボ第1回（RAU DEF - FREEZE!!!）

## 概要・やりたいこと

[reference-beat.md](../design/reference-beat.md) の Phase 0。実リファレンス曲1曲を分析パイプライン候補（ステム分離・BPM/キー検出・音声→MIDI）に通し、**何が実用精度で動くか**を見極める。あわせて初の分析レポートを書き、「わかる」柱（言語化）の書式を固める。

対象曲: **RAU DEF - FREEZE!!! feat. Sugbabe**（https://www.youtube.com/watch?v=YNQ9DP3BbRw）

**成功基準**

1. BPM/キー検出・ステム分離品質・MIDI化精度のそれぞれに「使える/使えない」の判定がつく
2. 初レポートが書けて、本人の耳の知覚と答え合わせできる
3. 結果が `docs/labs/reference-beat.md` に記録される

## 前提・わかっていること

- 2026-08-03 の `/dig` で確定:
  - **本丸は上モノの音色・質感**（本人は「HIPHOPの中のメロディアスなやつ」として聴いている）。上モノ分析（分離品質・コード抽出）は技術的に一番不確かな領域でもあるので、実験の厚みをここに置く
  - 進め方は Claude 自走→最後にまとめてレビュー（ステム試聴・好きな瞬間のマークはレビュー時に実施）
  - 音源は YouTube の MV 音声（MVエディット混入がないか波形確認してから使う）
- 環境調査済み: ffmpeg あり / ディスク244GB空き / **yt-dlp 無し**（LaLaが探す `/opt/homebrew/bin/yt-dlp` にも無い＝このマシンではLaLaのURL取り込みも現状動かない）/ Python は homebrew 3.14 のみ（torch の wheel が追いつかない可能性が高く、ラボには 3.12 を別途入れる）
- 分析は曲ごと1回の低頻度処理なので外部Python、というアーキテクチャは [reference-beat.md](../design/reference-beat.md) 参照
- ツール候補: demucs（4分割 htdemucs＋6分割 htdemucs_6s）・basic-pitch・librosa/essentia。どれを最終採用するかはこのラボの結果で決める（planでは固定しない）

## ログ

### 試したこと・わかったこと

- BPM 97.600（±0.05 で素点が半減する鋭いピーク＝完全固定テンポ）。キーは♭5つ（D♭ major / B♭ minor）で、
  ベースの音名分布の上位7音がスケールと完全一致して独立に裏が取れた
- コード進行は「ループ長で畳んでから当てる」と一気に安定した。6分割の piano/guitar/other が独立に同じ4小節進行を出す
- demucs が MPS で 3:50 の曲を 15〜17秒で分離。**ライブラリを増やすコストが実質ゼロ**と分かったのが今回いちばん効く発見
- 詳細な判定表と落とし穴は labs 側に集約（planには残さない）

### 方針変更

- **Brewfile への追記は不要だった**（`brew 'yt-dlp'` は記載済みで未インストール状態）。全体 `brew bundle` は
  無関係な20数パッケージの更新を巻き込むため、yt-dlp だけをスコープした Brewfile 経由で導入した
- **スクリプトを1本にせず7本に分けた**（overview / basics / stems / arrange / groove / topline / analyze）。
  Phase 1 の制約カードは「信頼できた分析だけ載せる」ので、項目ごとに差し替えられる粒度にしておく方が効く
- **basics.py の BPM 推定を2回作り直した**。ビートトラッカー任せ → 剛体グリッド（全長粗探索）→ 窓で候補を出して
  全長で精密化、の順。1回目は残差50ms、2回目は 122.0 BPM という別物を返していた（理由は labs 参照）
- **`stems.py` / `arrange.py` は plan に無かったが追加した**。「分離品質の所見」と「構成マップ」を出すのに、
  ステム単位の在/不在が要るため。レビュー用の聴きどころ小節番号もここから出している
- **`excerpts.py` を追加した**。レビューが「4分の音源の該当秒にシークする」作業になっていて始めるのが重い。
  確認する順に番号を振った短いクリップを切り出す形にした。特に**推定コードをサイン波で原曲に重ねる**
  クリップは、合っていれば溶け違えば濁るので、コード名を読むより速くて確実な検算になる
- **リファレンスの置き場を `~/Music/daw/references/<曲名>/` から `<プロジェクト>/references/<名前>/` に変更**
  （実装後にユーザーと相談して確定。[../design/reference-beat.md](../design/reference-beat.md) に記載）。
  共有ライブラリを作ると命名規則・重複・孤児を全部考える必要が出るが、横断レビューは
  `~/Music/daw/*/references/*/report.md` の glob で足りるので第2のルートを作る理由が無かった。
  ラボ第1号だけは対応するプロジェクトが無いため単独フォルダのまま残す
