# ノイズ除去ラボ — 要否と方式を実素材・実耳で確定する

## 概要・やりたいこと

宅録ボーカル（SM58 → UltraLite mk5）のノイズ除去機能を LaLa に入れるかどうか・入れるならどの方式かを、
**実装前にラボで確定する**。stem-model-lab（`2026-08-14-1912-stem-model-lab.md`）と同じ型:
判定基準を試聴前に固定し、ブラインドで聴き、結論を `docs/labs/` に記録する。**本planでは実装しない**。

背景の判断（2026-08-18 /dig）:

- 発端は「RXのような品質のノイズ除去にどこまで迫れるか」。調査の結論は、単機能デノイズなら
  オープンソースNNで RX Voice De-noise に匹敵し得る（RXの独走は修復スイート全体の話）
- ただし**本人はまだ具体的に困っていない**（予防的・品質向上の探索）。さらに音楽ミックスでは
  マスキング（ビートが鳴っている間は小さいヒスが聴こえない現象）により、ノイズが問題になるのは
  歌の隙間だけ、というのが歌モノの通説。**「そもそも要るか」から耳で確認する価値がある**
- feature-scope の判断軸（使用頻度×恒常コスト）に照らし、「困っていないのに作る」を避けつつ、
  サブ目的（作りながら理解を深める）にはラボ単体でも投資価値がある

### 実装時の既決事項（ラボの結論を受けた実装planへ引き継ぐ。ここで蒸し返さない）

- 適用の形 = **リージョン右クリック＋「トラック全体へ適用」ボタン**（オフライン処理）。
  ノイズはセッション（トラック）の属性なので一括手段は必須
- **リアルタイムFXスライスは不採用**（品質天井が RNNoise 級に落ち、歌唱の削れリスク最大。
  既存FX設計「常在・バイパスなし」とも不整合）
- **トラック属性での自動適用は不採用**（録音フローに非同期処理が絡む恒常コスト。
  明示適用で「毎回手で当てるのが苦」と分かってから再検討）
- NN採用時は **dry/wet と除去音検聴を必須装備**にする（ブレス・空気感の削れ事故の運用カバー）
- 古典採用時のノイズプロファイル取得は**テイク内の最静区間の自動検出**（手動範囲指定UIは作らない。
  ラボもこの方式で試験するので、勝てばそのまま製品仕様として再現できる）
- オフライン加工の実装の型は `2026-08-18-1028-audio-transpose-stretch.md`
  （非破壊パラメータ＋バックグラウンドレンダリング＋指紋キャッシュ）を参照。ただしNNは処理が
  分単位なので「読込時に再生成」をそのまま流用できるかは実装digで判断（WAV永続化が要る可能性）

### 方式の背景知識（/dig 中の調査。ラボの仮説にあたる）

- **古典スペクトラルゲート**: ノイズプロファイルを学習して各帯域から引き算。声がノイズより
  十分大きい部分は素通しになり**構造的に声を壊しにくい**。副作用は低SNR部（ブレスの端・語尾）の
  シュワシュワ音（ミュージカルノイズ）。RX自身のプロファイル学習モードもこの系譜
- **NN**: 時間×周波数の各マスを声/ノイズ判定してマスクやフィルタを掛ける（RoFormer系はマスク推定、
  DeepFilterNet3 は複素スペクトルへの deep filtering を含む方式で、一括りに「マスク方式」ではない）。
  正しいときは声の最中のノイズも取れて古典より上。誤ると**ブレスが痩せる・空気感が滑らかになる・
  語尾の余韻が縮む**。いずれも生成系修復（音を合成し直す方式）とは別物だが、
  **フィルタリングでも音色は変わり得るため「別人にならない」とは断定せず、耳で評価する**
- **DeepFilterNet3 は会話音声で学習**されており、ラップに強く歌のロングトーンに弱い可能性。
  RoFormer 系 denoise は音楽（歌唱込み）向け
- 速度の見立て: 古典＝ほぼ即時、DFN3＝実時間の数%、RoFormer系＝実時間の1〜2倍
  （stemlab 実測: 同系の BS-RoFormer SW が MPS で約230秒の曲に315秒。denoise は単機能なので
  やや軽い想定。`--device mps` 必須・auto は CPU に落ちる罠も stemlab で確認済み）
- マスキング: ビートと同時に鳴っている -50〜-60dBFS 程度のヒスは通常聴こえない。
  ノイズが露出するのは歌の隙間・ビートが薄いセクション

### ラボ設計の裁量事項（planレビューで直してよい）

- 置き場所: `tools/noiselab/`（venv は `tools/noiselab/.venv`。既存 reference venv に依存を足さない）
- 採点軸（Step 1）: **①ノイズの取れ具合 ②声・ブレスの損傷 ③アーティファクト（シュワシュワ音・水中感）**
  を、**ソロ／ミックス中の両文脈**で採点（原音比。**①は -2〜+2、②③は 0/-1/-2 のみ** — 尺度の定義は
  Phase 3 と同一）
- **拒否条件**: **①②③いずれかの軸に -2 が1行でも付いた候補×強さは不採用**（他が良くても覆らない。
  ①の -2 ＝明確なノイズ悪化は**便益行でなくても**拒否する — 便益に数えない行も安全性の監視には使う。
  これが無いと「便益行 +1・非便益行で明確な悪化・②③全て0」が採用条件を通ってしまう）
- 比較基準は**常に原音**（stemlab のようなペアX/Y化は不要。demucs と違い「無加工の原音」という
  絶対基準が存在するため。ただし**候補名は匿名化**する）
- 採用条件（**相対1位では採用しない**。便益と損傷の両方をゲートにする）。まず
  **便益行 = Step 0 で「気になる」となった行（素材×文脈）に対応する行**と定義する
  （気にならなかった行の①は便益に数えない — 聴こえないノイズを取っても意味がない。
  それらの行は①の明確悪化（-2 拒否）の監視と②③の安全性評価に使う）。拒否条件を通り、かつ候補×強さごとに次の3つを
  **すべて**満たすもののうち、**便益行の①合計**が最も高いもの:
  1. **便益行の①合計が正**
  2. **便益行の過半数で ① が +1 以上**
  3. **②声・ブレスの損傷 と ③アーティファクト は、それぞれ全行（便益行に限らない）の中央値が 0**
     （＝過半の行が「原音と区別つかない」。散発的な -1 は許すが、-2 が無くても
     広範な -1 の軽度劣化と微小改善の交換は許さない。中央値集約は stemlab の前例に合わせる）

  同点なら②③の合計が良い方 → それでも同点なら**古典を優先**（実装が軽く・依存が少ないため）。
  **条件を満たす候補が1つも無ければ「方式なし＝実装見送り」で確定**
- **古典のノイズプロファイル取得は、実装で使う方法と同じにする**: 「テイク内の最静区間
  （最小RMSの1〜2秒窓）を自動検出して学習」。頭の無音5秒を直接与える理想条件では試験しない
  （ラボで勝っても製品で再現できない結果を防ぐ）。**探索範囲から先頭5秒（意図的無音）を除外する**
  — 除外しないと最小RMS探索がほぼ確実に頭5秒を選び、「直接与えない」だけの実質理想条件になる。
  実運用のテイクに意図的無音は無いので、歌の隙間から拾わせるのが正しい試験条件。
  この自動検出方式がそのまま実装の仕様になる（手動範囲指定UIは作らない。検出品質が悪ければ
  その時点で古典の実力として採点に反映される）。頭5秒は Step 0 のノイズフロア実測専用

- [ ] **処理チェーンの契約を固定**（全候補共通。残差と採点はこの順序が前提）:
  1. モデルの要求SRへ変換（DFN3 は **48kHz 固定**。録音SRと違う場合はリサンプル）
  2. モデルの遅延（STFT / lookahead）を補償してサンプル整列
  3. 元SR・元フレーム長へ復元

     声を削った候補ほど正規化量が変わり、比較が偏る）

- [ ] 処理マトリクスを生成: **素材2 × 候補3 × 強さ2段階 = 12本**

        古典 = `prop_decrease` **0.5 / 1.0**、NN = dry/wet **50% / 100%**。
        実測の減衰量（無音部のRMS差）は結果として記録する
  - [ ] 各処理で**除去音ファイル**（上記契約の手順5）も生成 = 12本。削られた音に声が
        混ざっていないかの検聴用（RXの「output noise only」と同じ運用）
  - [ ] ソロ用に加えて**ミックス文脈版**も生成する。生成方法は Step 0 と**同一の信号経路**に固定:

- [ ] **提示ファイルの自動検査**（Phase 3 の前に必ず実行。壊れたファイルに人間の耳を使わない）:

  - [ ] NaN / inf 無し・クリップ（|x| ≥ 1.0）無し
  - [ ] **提示版 + 除去音 ≈ 原音**（残差の定義どおりに再構成できることの検算）
  - [ ] **遅延補償の実検査**: 声区間の相互相関で原音に対する提示版の推定ラグを候補ごとに求め、

  - [ ] 匿名フォルダのファイル数が blind-map のエントリ数と一致
- [ ] ブラインド試聴セットを準備:
