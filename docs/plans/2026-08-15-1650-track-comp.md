# トラックCompのDSP・エディタ実装（FXスライス4）

## 概要・やりたいこと

FXスロットの Comp（現在ガワのみ・`compEnabled` のON/OFF＋保存だけ実在）に中身を入れる。mixer-fx.md の6スライス中スライス4。**track-eq（スライス3・2026-08-15-1506）実装後に着手する**（信号チェーン位置と保存versionが依存）。

- 「素直で予測可能」な透明コンプを1本作る。定式化は Giannoulis, Massberg & Reiss "Digital Dynamic Range Compressor Design—A Tutorial and Analysis" (JAES vol.60 no.6, 2012) に従う: feedforward・dBドメイン検波・ゲイン計算後のGR（ゲインリダクション）を**dB単位で平滑化**。平滑化器は **smooth branching を選ぶ**（原論文の第一推奨は smooth decoupled。branching は attack/release 切替点でゲイン勾配が不連続になり得る代わりに時定数が設定値どおりになる、と論文自身が明記しており、**滑らかさより時定数の予測可能性を優先する**という本プロジェクトの学習目的に沿った選択。出力振幅の連続性は回帰テストで固定し、勾配不連続由来の可聴性は耳確認で監視する）。dBドメイン平滑化の利点は入力音量によらずAttack/Releaseが設定どおりの時間で効くこと（Logicでいう Platinum Digital と同系統の透明デジタル型。内部実装が同一という主張はしない）
- 学習のサブ目的: 「静的＝伝達カーブ（Threshold/Ratio/Kneeの形）」と「動的＝GRが時間でどう動くか（Attack/Releaseの効き）」の両面を目で見えるようにする（Logicは前者＋針メーターのみ）
- UIは ui-principles.md「操作は削る、概念は隠さない」: ノブは5個に絞り、固定値（Knee）は静的ラベルで概念だけ見せる（EQの「12dB/oct」と同じパターン）

## 前提・わかっていること

### 確定仕様（2026-08-15 の /dig で決定）

- **5ノブ**: Threshold / Ratio / Attack / Release / Make Up（手動。自動ゲインは作らない — 「コンプは音を小さくする道具→自分で戻す」の因果を体で覚えるため）
- **Knee は 6dB soft 固定**・「Knee: 6dB (soft)」の静的ラベル表示（伝達カーブの丸みでも見える）
- **検波サイドチェインHPF**: 「Detector HPF 80Hz」トグル1個・既定OFF（2mix状ループ素材でのポンピング対策。ベース/キック単体では逆効果なので既定OFF・常時ON固定にしない）
- **初期値は中立スタート**: Threshold 0dB（挿した直後はほぼ無効。下げていく所作がコンプの核心）。他は実用帯を既定に
- **視覚表示**: 左=伝達カーブ（現在の入力レベルの光点付き）＋右=GR履歴（横に流れる「何dB下がってるか」の軌跡）＋GRメーター。表示は操作ではないのでノイズ扱いしない
- **SlotPill の Comp 行にミニGRバー**: エディタを開かなくても掛かり具合が見える。SlotPill はミキサーとFXパネルで共有部品（`MixerOverlay.h:52`・`FxEditorView`）なので、1箇所実装で両方に出る＝Logicのチャンネルストリップ常設GR表示と同じ用途（一覧で掛かりすぎを発見）
- **Compピルの既定をOFFに変更**（現状 `PlaybackSnapshot.h:36` は既定true・音に未結線）。コンプはEQと違い「保証された中立設定」が無い（float音声は0dBFSを超えうるためThreshold 0dBでもGRが起き得る）ため、ピルを真のバイパスにする。旧バージョンの保存データは読込時にOFFへリセット（DSPが無かった頃のtrueは無意味なため）
- **操作はノブのみ・伝達カーブは表示専用**: カーブ上ドラッグは足さない（同じ値を変える経路が増えるとundo・dirtyの区切り揃えの負担だけ増える。グローバルルール「経路を減らして揃える」）。数値の直接入力もEQ同様後回し
- **undo対象外・全変更経路でdirty化**（EQ・フェーダーと同じ扱い。復元手段はノブのダブルクリックで既定値リセット）

### ノブの範囲・既定値

| ノブ | 範囲 | 既定 | 備考 |
|---|---|---|---|
| Threshold | -60〜0dB | 0dB | 中立スタート |
| Ratio | 1:1〜20:1 | 4:1 | 対数スケール。∞:1は作らない（リミッターはスライス5のMaster常在） |
| Attack | 0.1〜100ms | 10ms | 対数スケール |
| Release | 10〜1000ms | 100ms | 対数スケール |
| Make Up | 0〜+24dB | 0dB | |

### 見送り（将来のキャラ付け・スコープ外）

- リリース二段化（LA-2A系の「速い成分＋数秒の戻り」）: 透明コンプが不足に感じたときの最有力の足し方として温存
- サチュレーション: 独立FXとして別途（コンプ内に混ぜない）。固定チェーン [EQ][Comp][Ext] のどこに置くかはその時決める
- オーバーサンプリング: 速いAttackのエイリアシングはリミッター級の極端設定でのみ問題化する。常用域では不要で、「50行で簡単」を保つ方を取る
- 自動リリース・プログラム依存挙動・lookahead・Mix(パラレル)ノブ

### DSP方針

- **構成**: 検波（|L|,|R|→dB。**dB変換は有限フロア必須**: `juce::Decibels::gainToDecibels (level, -120.0f)` — 素の log10(0) は -inf になり、「出力dB−入力dB」型のGR計算で -inf − -inf = NaN が出る。-120dBはUI下限-60dBより十分下で聴こえ方に影響しない）→ ゲイン計算（Threshold/Ratio/soft knee 6dB）→ **GRをdBドメインで平滑化**（smooth branching: attack/release時定数の分岐型ワンポール。時定数の定義は α = exp(-1/(τ·fs))・ステップ入力でτ後に最終GRの63.2%へ到達）→ リニアに戻して両chへ適用 → Make Up。レイテンシゼロ
- **ステレオリンク**: L/R別々にHPF（ONのとき）→ 大きい方（max）で検波 → **両chに同量のゲインを適用**（別処理だと大きい側だけ下がり定位が動く）。maxを取ってからHPFは不可（整流済み信号のフィルタは意味が壊れる）。MIDIトラックはシンセ出力（EQ後）に適用
- **検波HPF**: 80Hz・12dB/oct biquad×2ch（検波専用コピー。主信号には掛けない）。フィルタ状態はIIR履歴と同じreset規則に加え、**HPFトグル自身の false→true 時にも履歴reset**（OFF中は状態が凍結するため、Comp全体の再有効化resetだけでは古い履歴が復活する）
- **パラメータ平滑化**: Threshold/Ratio/Make Up とも `SmoothedValue` を**サンプル単位（`getNextValue()`）で進める**。平滑化時間は**10msで統一**（`reset (sampleRate, 0.010)`。手動ノブ操作には即応と感じる速さで、Make Upのゲイン段差を十分短く均せる長さ）。EQの `skip(segLen)` 方式（区間末尾の値を区間全体へ適用）は持ち込まない — ブロックサイズで掛かり方が変わり（512なら最初から目標値・64なら段階的）、Attack 0.1ms級では聴こえ方自体が変わる上、ブロックサイズ不変テストと矛盾する。EQでセグメント方式だったのは係数再計算が重いからで、Compのゲイン計算はサンプル単位で走る軽い演算なので最適化自体が不要。Attack/Release は時定数係数なので即時反映でクリックは出ない
- **高速パス条件は `!compEnabled` のみ**（コンプに中立検出はしない）。OFF時は既存経路そのまま＝モノ経路のビット一致契約を維持。EQと組み合わせた全体の高速パス条件は「EQ側の条件 && !compEnabled」になる（EQ planの状態遷移に条件を1つ足す形）
- **ON/OFF切替のクリック対策**: EQ planと同じクロスフェード方式。compはチェーン内のComp段位置のdry/wetフェード1階層（EQのHPバンドフェードと同じ考え方）。高速パスへ移れるのはフェードと平滑化の完了後
- **状態reset**: エンベロープ（平滑化GR）・検波HPF履歴を、EQのIIR履歴と同じ条件（prepare/SR変更・シーク等の時間不連続）に加え、**完全バイパスからactiveへ入る直前**にもresetしてからクロスフェードを開始する（バイパス中は状態が凍結されるため、強いGR中にOFF→時間経過→ONの操作列で古いGRからwet信号が復帰する事故を防ぐ）。初期prepare時はフェードせずenabled状態へ直接同期し、実行中のトグルだけクロスフェードする。**例外: MIDIトラックは初回・再進入ともdryフェードイン（10ms）** — MIDI経路は常にtimelineJumped=falseで呼ぶ（シンセ出力は時間的に連続でリセットすると余韻にクリックが入る）ため即時同期の契機が無く、firstCallを即時同期にすると「再生中にComp ONした瞬間にMake Up分がジャンプする」クリック経路が生まれる。音声トラックは再生開始のシーク（timelineJumped=true）で即時スナップされるためこの差は出ない。`ScopedNoDenormals` は既存コールバックの慣行に従う
- **UI向けの値の受け渡し**: `TrackParams` のオーディオスレッド専用領域の流儀（`peakL/peakR` と同じ）で atomic を2つ追加 — ①ブロックごとの最大GR（ミニGRバー・GR履歴・GRメーター用） ②検波入力ピークの線形振幅（伝達カーブの光点用。フィールド名は `detectorPeakLinear` 相当に固定し、dB値を入れる誤実装を防ぐ）。GR atomicは**正の減衰量（0〜+∞ dB）で統一**し描画時だけ下向きにする（max-hold更新の符号事故防止）。検波入力レベルは**dBでなく線形振幅の正値でmax-hold蓄積**し、MainComponent側でdBへ変換する — 通常の入力dBは負なので `exchange(0)` のmax更新では初期値0に勝てず、単純storeでも無音時に0dBの光点が出る。無音時（-60dB未満）は光点を非表示にする。**消費は `MainComponent` の既存メータータイマーに一元化**（`MainComponent.cpp:697` の `exchange(0)` と同じパターン）し、各表示（SlotPill×ミキサー/FXパネル・Compエディタ）へ配布する — 複数UIが同じatomicを直接 exchange するとピークを奪い合うため。GR履歴はUI側でリングバッファに蓄積（0〜-24dB固定スケール・約5秒窓）。FFT級の忠実度は不要なのでAnalyzerTapのようなFIFOは使わない
- **伝達カーブは描画と音が同じ数式**: 静的ゲイン計算（入力dB→出力dB。knee含む・**Make Up適用前の静的圧縮特性**）を関数として切り出し、DSPとUI描画の両方が同じ関数を呼ぶ（EQの `getMagnitudeForFrequencyArray` と同じ思想）。Make Upを含めると+24dBまで出て縦軸上限0dBで描けない上、「圧縮の形」と「戻す量」を分けて見せる方が学習目的に合う
- **判断ロジックをui/に書かないルール**: ゲイン計算・エンベロープはUI非依存のクラスに置き、daw_testsで応答を固定する

### 既存コードの結線先

- `shared/PlaybackSnapshot.h` の `TrackParams`: `compEnabled` atomic既在（**既定をfalseへ変更**）。Compパラメータ6個（threshold/ratio/attack/release/makeup/scHpf）を個別atomicで追加（EQバンドと同じ経路: shared_ptr共有→再pushなしで即反映）。保存・バウンス用のプレーン値スナップショット構造も同様に分ける
- エンベロープ・HPF履歴などの実行状態は `TrackParams` のオーディオスレッド専用領域（リアルタイム再生専用）。バウンスは `TrackRender` へプレーン値スナップショット＋**独立した TrackComp を生成して開始時reset**（EQ planと同じ構造で競合排除）
- 信号順は mixer-fx.md 確定の **EQ → Comp → トラックgain/pan**。RTとバウンスで処理順を一致させる。**例外: モノ＋ステレオ混在のオーディオトラックだけはpan（クリップ合算時の焼き込み）→FXの順になる** — クリップ種別でpan法則が違い（モノ=等パワー/ステレオ=バランス）、合算後に単一の後段panとして適用できないため。モノのみ・ステレオのみ・MIDIはすべてpan前にFXが掛かる（RT/バウンス同順）
- 保存: `Project.cpp` currentVersion = **16**（EQのv15の次）。`fx.comp` に {enabled, threshold, ratio, attack, release, makeup, detectorHpf} を追加（キーは単位なし短名＝EQの freq/gain/q と同じ流儀）。v15以前の読込は既定値＋**enabledはfalseへリセット**
- UI: `FxEditorView` のCompスロットクリック → `FxDetailView::setBody()`（幅フル×高さ約224px）
- ミニGRバー: `SlotPill` に任意表示のGR描画を追加し、Compピルのみ有効化（ミキサー/FXパネル両方に自動反映）
