# リージョンのリピート（⌘R）・コピー/ペースト・ループ

## 概要・やりたいこと

リージョン/クリップの「繰り返し」まわりの操作を3つ足す。役割が被っていないので3つとも入れる。

| | 役割 | 他で代替できるか |
|---|---|---|
| **⌘R（複製）** | 今いる場所の直後に足す。連打で伸ばす | ループがあれば減るが、途中を変えたい繰り返しはこっち |
| **⌘C/⌘V** | 離れた場所・別トラックへ運ぶ | ⌥ドラッグで代替できるが、スクロール外へは実質無理 |
| **ループ** | 元を直すと繰り返し全部に反映 | これだけは代替なし。⌘R複製は複製後は別物になる |

対象は **MIDIリージョン・オーディオクリップの両方**。

Logic の「右上角ドラッグでループ」は、**同じ辺の数px違いで長さ変更とループが切り替わる**ため誤操作が多かった。本アプリでは辺を分ける（右端＝長さ変更 / 下辺＝ループ）ことでこれを避ける。

## 前提・わかっていること

### 決定事項

- ループのUIは**専用ハンドルのドラッグ**。右端リサイズとは辺を分ける（下辺）
- ループの途中だけ変えたくなったら「ループ解除 → ⌘R連打で組み直す」。**Loops to Regions 相当の展開機能は作らない**
- ループ・コピー/ペーストとも**オーディオクリップにも効かせる**
- Logic の Repeat ダイアログ（回数指定・Adjustment・Alias/Clone）は**作らない**
- エイリアス/クローン（元に追従する別リージョン）も**作らない**。「元に追従」はループだけで足りる

### 現状の実装（調査済み）

- **⌘Rはほぼタダ**。`TimelineView::duplicateAt`（`TimelineView.cpp:1365`）が既に「元の終端直後に置いて複製を選択状態にする」ので、**連打で伸びる挙動は自動的に満たされる**。`Shortcuts.h` に1行足して選択中アイテムに対して呼ぶだけ。MIDI/オーディオ両対応済み
- **ループの再生は安い**。MIDIは `Project.cpp:804` の `buildSnapshot` でノートを絶対PPQへフラット化しており、オーディオも `Project.cpp:790` で `ClipPlayback` を並べているだけ。**ループは展開時にエントリを増やすだけで PlaybackEngine は無改造**
- ただし同じ展開ロジックが `BounceRenderer.cpp:20`（`buildItemRender`）にもあり、`Project.cpp:801` のコメントで「変えるときは両方を見ること」と明記されている → **ループ展開は共通ヘルパーに切り出して2箇所から呼ぶ**
- `UndoStack` は `project.tracks` の構造コピーを積む方式なので、**Track配下のフィールドを増やせば自動的にundo対象**になる（`2026-07-25-sampler-instrument.md:59` の前例）
- リージョンの描画高は **84px**（`trackHeight` 92 − 上下余白8。`TimelineView.cpp:479`/`535`）。下辺に8〜10pxの帯を置いても本体は70px以上残る
- 右端8pxリサイズは**MIDIリージョンのみ**（`TimelineView.cpp:1003`）。オーディオはトリム自体がTier 1スコープ外で、右端は空いている
- リージョン選択は**常に1つ**（`selection` / `regionSelection` が排他。`TimelineView.cpp:997`）。複数選択は今回も入れない
- ⌘C/⌘Vの競合には前例がある。Deleteキーが `MainComponent.cpp:2385` で「**ノートが選択されていればノート、無ければリージョン**」と裁いている。`copySelection()` / `pasteAtPlayhead()` はどちらも空なら `false` を返すので、同じ形でフォールバックできる
- ショートカット追加は `Source/ui/Shortcuts.h` のテーブルが単一の真実の源（CLAUDE.md）。⌘?一覧は自動生成される
- **保存時のWAV GCはクリップボードを知らない**。`Project::save`（`Project.cpp:385`）は「`keepReferencedWavs` ＋ 現在のトラックのクリップ ＋ `sampleFile`」だけを保護し、それ以外の `clip-*.wav` を削除する。`audio` を shared_ptr で握っていても**実ファイルは消える**ので、「コピー → 元クリップ削除 → 保存」で再読込時に欠損する。`keepReferencedWavs` は undo履歴の保護に使われている既存の口（`Project.h:209`）で、クリップボードも同じ「モデル外からの参照」なのでここに乗せられる
- **⌘E（リージョン書き出し）はミュートを無視する既存仕様**。`MainComponent.cpp:1807` に「トラックのmute/solo・リージョン自身のmutedは見ない（明示選択が優先）」とあり、`BounceRenderer::buildItemRender` 側にも `muted` の判定がない。一方 `buildSnapshot` は `region.muted` で除外する → **展開ヘルパーにミュート判定を持たせると⌘Eが壊れる**
- **⌘Bの出力終端はスナップショットから取っていない**。`MainComponent.cpp:1625` がモデル側の `region.startPpq + region.lengthPpq` から別途算出している（「スナップショットには境界情報が残らない」ため）。オーディオは `trackRender.clips` の実エントリから取るので展開で自動的に伸びるが、**MIDIループは本体終端で切られる**
- **`updateContentSize` も本体終端しか見ない**（`TimelineView.cpp:890`）。ループ終端を足さないと長いループがビューポート外に出てスクロールできない

### 仕様（このplanで確定させたもの）

**⌘R（リピート）**
- 選択中のリージョン/クリップを、その終端直後に複製（既存の右クリック「複製」と同じ動作）
- 連打すると複製が選択を引き継ぐので後ろへ伸びていく
- **ループ中のアイテムは「ループ終端の直後」に置く**（本体終端に置くとループと重なる）

**⌘C/⌘V**
- コピー対象は選択中のリージョン/クリップ1つ。**`MidiRegion` / `Clip` を丸ごと値で保持する**（`name`・`muted`・`peakCache`・ループ設定も含む）。フィールドを列挙して詰め替えると、後からモデルに項目が増えたときに取りこぼす
- ペースト先は **再生ヘッド位置（グリッドスナップ）× 選択中のトラック**。型が合わないトラック（MIDIクリップボード→オーディオトラック等）では何もしない
- ペースト時に差し替えるのは**開始位置（`startPpq` / `startSample`）とID**だけ。ID（リージョン・ノート）は `allocateId()` で再採番
- ペーストしたものを選択状態にする（複製と同じ）
- クリップボードは `MainComponent` 保持のアプリ内メモリ。**プロジェクトを閉じる/切り替えるときにクリアする**（別プロジェクトの `audio` バッファや存在しない `fileName` を貼ることになるため）
- **クリップボードが参照するWAVをGCから保護する**。オーディオクリップをコピーしたまま元クリップを削除して保存すると、`Project::save` の GC が実ファイルを消す（前提セクション参照）。保存時に渡す `keepReferencedWavs` へクリップボードの `fileName` を加える（undo履歴の保護と同じ口に乗せる）
- ピアノロールが開いているときはノート側の⌘C/⌘Vが優先（既存Deleteと同じ規則）

**ループ**
- **ノートは各反復の末尾でマスクする**。現在も `Project.cpp:808` で本体境界（`regionEnd`）を越えるノートを切っており、ループでも同じ規則を**繰り返しごとに**適用する。境界をまたぐロングノートが次の反復へ持ち越されて音が伸びる／重なるのを防ぐ（最終ループ終端だけで切るのでは足りない）
- ループ中は本体の右端リサイズを**無効化**する（本体右端がループ部分に隠れて「真ん中でリサイズ」になり混乱するため）。長さを変えたいならループ解除してから
- ループ解除は**右クリックメニューの「ループ解除」**（ループ中のアイテムでのみ有効）。`L` キーは今回入れない（ドラッグで作るのだから解除も同じ文脈で足りる。⌘Rほど連打しない）
- ループ部分のクリックは本体と同じ扱い（選択・ドラッグで移動）。移動するとループごと動く
- **⌘T分割はループ解除**を伴う（左右どちらにループを引き継ぐか自明でないため）。分割可否の判定は従来どおり本体内のみ
- ミュート（⌃M）はループ全体に効く（既存 `muted` のまま）
- ⌥ドラッグ複製・右クリック複製・⌘C/⌘Vはループ設定ごと複製する。ただし**配置位置は各操作の既存仕様のまま**（⌥ドラッグ＝ドラッグ先、⌘V＝再生ヘッド位置）。「ループ終端の直後」に置くのは `duplicateAt` を使う**⌘Rと右クリック複製だけ**
- **リージョン書き出し（⌘E）はループを含む**（`BounceRenderer::buildItemRender` を共通ヘルパー経由にする）。ただし⌘Eは**ミュートを無視する既存仕様を保つ**（明示選択が優先）ため、展開ヘルパー自体はミュートを判断しない
- **バウンス（⌘B）はMIDIの終端計算をループ終端に直す必要がある**（`MainComponent.cpp:1625`）。「`buildSnapshot` 経由だから自動」ではない。オーディオ側はクリップの実エントリから終端を取るので展開だけで伸びる

**録音中の扱い（共通）**

既存の構造編集は冒頭で `engine.isRecording()` を見て no-op にしている（`toggleMuteSelectedItem` は `MainComponent.cpp:2703`、`splitSelectedItemAtPlayhead` は `MainComponent.cpp:2713`）。これに揃える。

- **⌘C（コピー）は録音中も許可** — モデルを触らないため
- **⌘R・⌘V（ペースト）・ループ編集（ハンドルドラッグ・ループ解除）は録音中no-op**

`TimelineView` は `TransportState&` しか持たず `PlaybackEngine` を知らない（`TimelineView.h:39`）。`TransportState::recordArmed` は**録音待機**であって `engine.isRecording()` とは別物なので流用できない。`TrackHeadersView::canReorder`（`MainComponent.cpp:373` で `[this] { return ! engine.isRecording(); }` を渡している）と同じ形で、**`TimelineView::canEdit` コールバックを MainComponent から渡す**。

⌘R（キー）だけをガードすると「右クリックからは録音中でも複製できる」不一致が残るので、**右クリックメニュー経由も実行時にこの判定を通す**。

右クリックメニュー5項目を洗うと、**MainComponentへ委譲する項目はガード済み・`TimelineView` 内で完結する3つが素通り**という構図になっている。受け口を作るついでに3つとも揃える。

| 項目 | 実行先 | 録音中ガード |
|---|---|---|
| ミュート | `TimelineView::toggleMuteAt` | **なし**（⌃Mは `MainComponent.cpp:2703` であり） |
| 複製 | `TimelineView::duplicateAt` | **なし** |
| 分割 | `TimelineView::splitAtPlayhead` | **なし**（⌘Tは `MainComponent.cpp:2713` であり） |
| 削除 | `MainComponent::deleteRegionAt` | あり（`MainComponent.cpp:1020`） |
| 書き出し | `MainComponent::startRegionExportFlow` | あり（`MainComponent.cpp:1739`） |

### Phase 0（モック）で決めること

以下はコードより先に触って決める。文字だけだと判断できず、実装後の手戻りが大きい。

1. **ループ長のスナップ方式**
   - 案A: **リージョン長の整数倍のみ** — モデルは `int loopCount`（0=ループなし、n=本体の後ろにn回繰り返す。総再生長 = `length * (1 + loopCount)`）。本体リサイズ時も回数据え置きで自然に伸びる
   - 案B: **グリッド単位で任意終端** — 4小節ループを6小節ぶんで切れる。末尾の切断は既存のリージョン境界マスクと同じ要領で書けるが、中途半端な終端が常に描画・移動・リサイズの考慮対象になる
   - **案Bを採るときは絶対位置でなく開始位置からの相対長で持つ**（`loopLengthPpq` / `loopLengthSamples` = 本体先頭からの総再生長）。絶対終端だと移動・ペーストのたびに書き換えが要り、書き換え漏れが即バグになる。不変条件は「0 = ループなし、それ以外は **`> lengthPpq`**（本体長より真に長い）」。`>=` にすると「見た目は繰り返しなしなのにループ扱いで右端リサイズだけ効かない」という状態が生まれるため、**ハンドルを本体終端まで戻したら 0 に正規化する**
2. **ハンドルの高さと出現条件**（推奨: **選択中のリージョンだけに出す**。未選択は1クリック目が必ず選択になるので「掴もうとしたら伸びた」が原理的に起きない。Logicは常時有効なのが事故の主因）
3. **右下隅（右端8px × 下辺帯）の優先順位** — リサイズとループのどちらに倒すか

> 過去に「ヒット幅が10px未満の操作は、合成クリックでテストが通っても実マウスでは掴めない」で刺さっているので、帯の高さは実際にドラッグして決める。
