# オーディオクリップの移調・タイムストレッチ

設計の真実の源: `docs/design/region-settings.md`「オーディオトランスポーズの設計」節（未決2項目と用途の記述を本planで確定）/
`docs/design/reference-beat.md`「帰結として浮上した将来の恒常的なコスト」節（⑤トランスポーズ/ストレッチ）

## 概要・やりたいこと

オーディオクリップに**移調（半音）**と**タイムストレッチ（長さのみ変更）**を非破壊パラメータとして持たせる。

用途は3つ:

1. **2本目以降のループ素材をプロジェクトのキー/BPMに合わせる**（本命）。1本目は採用時の逆コピーで
   合うが、2本目以降とライブラリの「キー以外は完璧」な素材はこれが無いと使えない
2. **録った素材（ボーカル・ラップ）のキー変え** — 歌いやすいキーを探る
3. チョップ素材のピッチいじり

`reference-beat.md` のフェーズ表で ⑤ に置かれていた項目。おすすめ5はすでに
`transposeSemitones` / `bpmRatio` を計算しているが（`GachaSession.h:150-151`）今は**表示専用**で、
「使える」と判定した素材を実際に使える状態にするのが本planのゴール。

## 前提・わかっていること

### /dig で確定した仕様（2026-08-18）

| 論点 | 決定 |
|---|---|
| 方式 | **長さ保持のピッチシフトのみ**。テープ式（リサンプル＝ピッチと長さが連動）は入れない |
| タイムストレッチ | **同時にやる**。エンジンは1つ（signalsmith-stretch）で両方扱う |
| 適用単位 | **クリップ（リージョン）単位のみ**。トラック単位は持たない |
| 破壊/非破壊 | **非破壊**。原音＋値を保持し、加工済みバッファをキャッシュ |
| 伸縮の指定 | **小節数で指定**（「このクリップをちょうど12小節にする」）。元BPMのメタデータを一切要求せず、グリッドに噛むことが直接保証される |
| プロジェクトBPMへの追従 | **追従しない**。BPMを変えたら吹き出しを開いて指定し直す |
| 極端な伸縮率 | **音楽的なハード制限なし**。吹き出しに倍率を併記し、±10%を超えたら色を変える（安全限界は別。後述） |
| 操作 | **右クリック → 専用の吹き出し**（ゲインとは別項目）。移調＋小節数の2項目 |
| キャッシュ | `project.json` には**値のみ**。加工済みバッファは**読込時に再生成**（WAV永続化しない） |
| 処理中の挙動 | **古い音のまま鳴らし、完了したら差し替える**（再生が途切れない） |
| おすすめ5からの自動適用 | **入れる**。敷いた時点で移調量と小節数が入っている |
| フォルマント補正 | **入れない**（オフ固定）。本命のループ素材（楽器）には不要。ボーカルで不自然だと感じてから足す |
| フェードの扱い | **一緒に伸縮する**（波形に対する斜線の相対位置が動かない） |
| 推薦の足切りフィルタ | **今回は触らない**（キー±2半音・BPM±10%のまま）。実際に加工した音を聴いてから判断する |

補足の判断:

- **移調の値域は ±12半音**（キー合わせなら±6で足りるが、往復の余地を見て1オクターブ）
- **色替えの閾値は 0.9〜1.1倍**。ライブラリの推奨レンジ（0.75〜1.5倍）より厳しいが、
  `reference-beat.md` の「±10%程度の近距離救済」に合わせる
- **単位は半音のみ**（セント/ファインチューンは持たない。`region-settings.md` の既決事項）
- 移調と伸縮は独立した2値なので、両方いじればテープ式を近似できる（+2半音 & 0.89倍）。
  ただし**音は真のリサンプルと同じにはならない**（1インスタンスで同時処理するので二重加工では
  ないが、位相ボコーダー特有の滲みが乗る。リサンプルも補間フィルタは通るが、この滲みは無い）。
  「テープ式が欲しい」となったら別途30行で足す

### 見え方（`region-settings.md` の可視性の原則をそのまま適用）

> 痕跡が見えるように作った項目は、表示場所が要らない。

- **移調は痕跡が見えない → `+2` バッジ**（0以外のときだけ。リージョンゲインのdBバッジと同じ流儀）
- **ストレッチは長さが変わる＝痕跡が見える → バッジ不要**
- 常設インスペクタは作らない（既決）。吹き出しは**ゲイン**と**移調・伸縮**の2つで打ち止めにする

### ライブラリ（2026-08-18 に実物で裏取り）

**signalsmith-stretch**（https://github.com/Signalsmith-Audio/signalsmith-stretch）

- **MIT ライセンス**（商用利用可）
- ヘッダ中心だが FFT で **Signalsmith Linear に依存**する
- **公開タグは 1.0.0 / 1.1.0 の2つだけで、main のヘッダは 1.3.2**（`git ls-remote --tags` で確認）。
  → **タグでなく commit SHA で pin する**
- **既定コンストラクタは `std::random_device` でシードする**（`SignalsmithStretch()`）。
  別に **`SignalsmithStretch(long seed)`** がある。
  → **必ずシード付きを使う**。既定のままだと「読込時に再生成」した音が起動ごとに変わり、
  回帰テストも不安定になる（本planの設計と両立しない）
- **`exact(inputs, inputSamples, outputs, outputSamples)`** がある（バッファ全体を一括処理）。
  レイテンシ補償・flush を内部で吸ってくれる可能性が高い → Phase 1 で採否を確定する
- 上流の `CMakeLists.txt` は **CMake 3.24 を要求**するが、**LaLa は 3.22**（`CMakeLists.txt:1`）。
  → `add_subdirectory` せず、FetchContent で取得して include ディレクトリだけ足す方式を第一候補にする
- API: `setTransposeSemitones()` ＋ 入出力バッファ長の差でストレッチ。1インスタンスで両方同時
- 品質の但し書き: ピッチは複数オクターブ可だが、**ストレッチは 0.75〜1.5倍が最良**
- フォルマント補正 `setFormantFactor()` / `setFormantBase()` を持つ（今回は使わない）

次点は SoundTouch（LGPL・軽量だが品質は中）。品質が実用に足りなければ切り替える。

### データモデルの方針

#### 原音座標を真実の源にする

- `Clip::offsetSamples` / `lengthSamples` / `fadeInSamples` / `fadeOutSamples` は
  **すべて加工前（原音）のサンプル数**のまま
- 保存するのは `transposeSemitones`（int）と **`stretchRatio`（double）**。
  小節数はUIの入力手段であって保存値ではない（BPM追従しないと決めた以上、小節数を保存すると
  BPM変更時に意味が変わってしまう）
- 値を往復させても（8小節→12小節→8小節）**丸め誤差が累積しない**

**長さのメソッドを2本に分ける。** 現状の `Clip::totalLengthSamples()` は
`clampFades()`（原音座標の不変条件・`Project.h:66`）からも描画からも呼ばれている。
これを実効長に寄せると**フェードのクランプまで実効長基準になり、不変条件が壊れる**:

| 用途 | 使うもの |
|---|---|
| 原音側の不変条件（`clampFades`）・分割・保存 | `sourceTotalLengthSamples()`（現行の定義のまま） |
| 描画・ヒットテスト・再生・終端計算 | `renderedTotalLengthSamples()`（`activeDomain` 由来） |
| 再生時のフェード長 | **chain 座標変換**（下記。単純な `× ratio` では合わない） |
| フェードのドラッグ | タイムライン差分を **chain 座標変換の逆**で原音座標へ戻してから保存 |

**フェードは `× ratio` では写せない。** フェードは「ループの連なり全体」の両端に掛かる
（`region-settings.md` の既決事項）ので、反復ごとの丸めが積み上がる。
本体1サンプル・`ratio = 1.5` なら実効本体長は `round(1.5) − round(0) = 2` で、
100反復の全長フェードは実効200サンプルであるべきだが、`round(100 × 1.5) = 150` になる。

**「完了した本体数」と「本体内の端数」に分解して写す**:

```
renderedBodyLength = mapBoundary(offset + length) - mapBoundary(offset);
fullBodies = fadeSamples / lengthSamples;      // 整数除算
remainder  = fadeSamples % lengthSamples;
renderedFade = fullBodies * renderedBodyLength
             + (mapBoundary(offset + remainder) - mapBoundary(offset));
```

- フェードアウトは**終端側から**同じ規則で求める
- ドラッグの逆変換も `/ ratio` ではなく**この chain 変換の逆**を使う
  （実効長を `renderedBodyLength` で割って本体数を出し、余りから本体内の端数を引き戻す）

#### 要求値と実効値を分ける（共有する `RenderedDomain` と、クリップ固有の view）

**`lengthSamples × stretchRatio` を見かけ長として直接使ってはいけない。** レンダリングが
終わる前にこれを使うと、再生長と実バッファ長が食い違う（1.5倍なら 0.5N の無音が入り、
0.5倍なら反復が重なる）。

そこで **「共有される加工結果」と「クリップ固有の切り出し」を別の型に分ける**。
1つにまとめると、同じ結果を共有する分割後の左右が**別々の view を表現できない**:

```
// キャッシュの単位。生成後は書き換えない。複数クリップで共有する
struct RenderedDomain {
    shared_ptr<const AudioBuffer<float>> audio;       // ドメイン全体の加工済み（無加工なら原音そのもの）
    shared_ptr<const AudioBuffer<float>> sourceAudio; // 原音。指紋のアドレス再利用を防ぐ強参照
    int64  audioBaseOffset;                           // audio 内でドメイン先頭が始まる位置
                                                      //   無加工 = domainOffset / 加工済み = 0
    int64  domainOffset, domainLength;                // 覆っている原音範囲
    int    semitones; double ratio; double sampleRate;
    vector<float> peakCache;                          // ドメイン全体の波形キャッシュ
};

// Clip 側（共有しない）
shared_ptr<const RenderedDomain> activeDomain;
// view は activeDomain と自分の範囲から導く（下記の式。フィールドに持ってもよいが真実の源は式）
```

- **描画・ヒットテスト・再生・終端計算はすべて `activeDomain` と、そこから導いた view だけを見る**。
  `transposeSemitones` / `stretchRatio` は**要求値**で、まだ音になっていないかもしれない値
- 波形キャッシュもドメイン全体で1本。クリップはその部分範囲を参照して描く
  （チョップを何個作ってもピークの再計算が起きない）
- ただし**view の両端は 512 サンプル区切りに揃わない**ので、そのままだと
  **境界の外にあるピークが見えてしまう**（チョップした右側に、左側にしかない強い
  トランジェントが描かれる）。**先頭と末尾の部分区間だけ実バッファから集計し直す**
  （中間は共有キャッシュをそのまま使う）
- 無加工（`semitones == 0 && ratio == 1.0`）のときはレンダリング不要で即座に作れる
  （`audio` は原音そのもの・`ratio = 1.0`）。既存プロジェクトはこの経路だけを通る
- 帰結として、**値を変えてからレンダリングが終わるまでは見た目も音も古いまま**で、
  同時に切り替わる。不整合が原理的に起きない

#### view は「絶対境界の差」で求める（独立に長さを丸めない）

`renderedLength = round(lengthSamples × ratio)` と**独立に**計算すると、隣接する view の
境界が一致せず、**バッファ終端を越えて読む**ことがある。
（例: `domainLength = 2` / `ratio = 0.5` → 加工バッファ長は `round(1.0) = 1`。
右子 `offset = domainOffset + 1, length = 1` は `bufferOffset = round(0.5) = 1`・
`renderedLength = round(0.5) = 1` となり、長さ1のバッファの `[1, 2)` を読む）

**必ず絶対境界から引く**:

```
// ドメイン render 座標への写像（絶対位置 → ドメイン先頭からの距離）
mapBoundary(srcPos) = round((srcPos - domainOffset) * ratio);

start = mapBoundary(offsetSamples);
end   = mapBoundary(offsetSamples + lengthSamples);
renderedLength = end - start;      // 隣接 view の境界は定義上一致する

// 再生時に audio を読む位置。audioBaseOffset を忘れると無加工の
// 分割済みクリップが原音の先頭から鳴る
readOffset = audioBaseOffset + start;
```

- 分割も同じ式を通す: 表示座標の分割点 → 原音境界へ逆算 → **その原音境界からこの式で
  canonical な表示境界を求め、左右で共有する**
- **`end == start` になる極端に短い view は分割不可**にする（長さ0の view を作らない）

#### レンダードメイン（分割を再レンダーなしで成立させる）

クリップは自分の範囲だけでなく、**その render が覆う原音範囲＝レンダードメイン**を持つ。

- `Clip` に **`renderDomainOffset` / `renderDomainLength`**（原音座標・**永続化する**）を追加。
  新規・取り込み・録音のクリップでは**自分の範囲と同じ**
- 指紋の範囲は**クリップの範囲でなくドメイン**。`RenderedDomain` はドメイン全体を覆う
- クリップの view は上記の**絶対境界の差**で導く（独立に長さを丸めない）

**分割は再レンダーしない。** 子は親のドメインをそのまま継承し、`offsetSamples` /
`lengthSamples` だけが変わる。**同じ `RenderedDomain` を共有し、view だけが異なる**ので:

- **⌘T が即座に効く**（チョップの連打が重くならない）
- **境界の音が分割前と厳密に一致し、それが再起動後も保たれる**（ドメインが永続なので、
  読込時も同じ1本をレンダーして同じように切る）
- **1本のループを何個にチョップしても、レンダーは1本を共有する**（メモリ・時間とも有利）
- 分割はレンダーを伴わないので**失敗し得ない**。トランザクション・同時landing・
  ロールバックのいずれも要らない

**境界は render 座標で1回だけ決め、左右の view がその同じ値を共有する**（隙間も重なりも
定義上生じない）。原音側の `offsetSamples` / `lengthSamples` はその境界から逆算する。

**値を変えたらドメインをそのクリップ自身の範囲へリセットする。** 1小節のチョップのために
8小節を再レンダーしないため。値を変える瞬間は音が変わるのが期待されているので、
そこで境界の連続性が切れても違和感にならない。

**読込時に検証する**（包含関係だけでは負の開始や原音外のドメインを通す）:

- `domainOffset >= 0` かつ `domainLength >= 1`
- **checked addition** で `domainOffset + domainLength <= 原音の長さ`
- ドメインが `[offsetSamples, offsetSamples + lengthSamples)` を含む

いずれかを満たさなければ**クリップ自身の範囲へリセットする**。

#### `activeDomain` の不変条件（構造変更で壊さないための契約）

`splitClip()` は `left = clip` / `right = clip` の構造体コピーなので（`Project.cpp:80`）、
何もしないと**両方が分割前の全長を覆う view を持つ**。次を不変条件として強制する:

> **`activeDomain` は、原音・SR が現在の `Clip` と一致し、そのドメインが
> `[offsetSamples, offsetSamples + lengthSamples)` を含んでいれば有効。
> 要求値（`semitones` / `ratio` / 要求ドメイン）との一致は求めない。**

要求ドメインとの一致まで求めると、**値を変えた瞬間に要求ドメインがクリップ自身の範囲へ
リセットされるため必ず不一致になり、無加工へ落ちて「完了までは古い音」の仕様が壊れる**。
包含だけを条件にすれば、古いドメインの view を鳴らし続けたまま新しいドメインを裏で作れる。

- **成功時は新しいドメインと要求値へ同時に切り替える**（音・長さ・波形が一斉に変わる）
- **巻き戻しは「モデルの変更」なので必ず dirty 化する**。要求値を保存して dirty が消えた直後に
  失敗すると、**ディスクは新しい値・メモリは旧値**になる。undo には積まなくてよいが、
  dirty にして終了時の再保存を促す
- **失敗時は `semitones` / `ratio` に加えて要求ドメインも実効ドメインへ戻す**
  （要求だけが進んだ状態を残さない＝「永続状態＝鳴っている音」を保つ）
- **分割では `activeDomain` を差し替えない**（ドメインが同じものを共有する）。変えるのは view だけ
- **undo state には `activeDomain` を入れない**（`UndoStack` へ積む際にクリアする）。
  `UndoStack` は `std::vector<Track>` を**値で**保持し（`UndoStack.h:47`）、`maxDepth = 100`
  （`UndoStack.h:22`）。3分ステレオ float の render は約69MB なので、そのまま持たせると
  調整を重ねただけで**数GB**を抱え込む。
  undo/redo 後は reconcile がキャッシュから引き直し、無ければ再レンダーする
  （直前の値はキャッシュに残っている可能性が高く、実際にはヒットすることが多い）
- **`activeDomain` の指紋と要求指紋が食い違っている間は、長さ依存操作を無効にする**
  （分割・「終端直後へ複製」など）。`startSample` は保存された位置で landing 後に追従しないため、
  実効 1.0 / 要求 1.5 の処理中に中央で切ると、右の開始は旧長の 500 のまま左が 750 になり
  **250 サンプル重なる**
- reconcile は**関数を1本**にして、構造が変わり得る経路（分割・複製・ペースト・削除・移動・
  undo/redo・プロジェクト読込・ガチャの仮配置/キャンセル）から呼ぶ。
  **包含が崩れていたときだけ**ドメインをクリップ自身の範囲へリセットして積み直す

#### 非同期結果の返し先は「指紋」で解決する（`Clip::id` を足さない）

`Clip` に安定IDが無いので、index で結果を返すと削除・分割・複製・undo・プロジェクト切替後に
**別のクリップへ結果が適用され得る**。

対処として `Clip::id` を新設する案もあるが、本planは**指紋キーのキャッシュ**を採る:

- 指紋 = `(原音バッファの識別, renderDomainOffset, renderDomainLength, semitones, ratio, SR)`
- **キューへ積む request 自身も `shared_ptr<const AudioBuffer<float>> sourceAudio` を保持する**。
  `RenderedDomain` の強参照は**完成後**の話なので、完成前に最後の参照元クリップが削除されたり
  プロジェクトが切り替わると、**ワーカーが読んでいる最中の原音が解放される**。
  request が持てばジョブ終了まで生存が保証される
- **原音の生ポインタを識別に使うだけでは誤ヒットする**: クリップ削除で原音が解放され、
  別の `AudioBuffer` が同じアドレスに確保されると、古い加工音を拾う。
  対処として **`RenderedDomain` が原音の `shared_ptr` を保持する**（キャッシュに残っている間は
  そのアドレスが再利用されない）。**LRU のバイト上限には原音のサイズも含める**
  （代案は再利用されない非永続の source token を振る方式だが、`clip.audio` を差し替える
  すべての経路でトークンを設定する規律が要るので採らない — 強参照なら自動で守られる）
- レンダリング結果は **`map<指紋, shared_ptr<const RenderedDomain>>` の、バイト上限付き強参照 LRU**
  に入れる。**結果をクリップへ「送る」のではなく、クリップが自分の指紋で引く**
- **`weak_ptr` にはしない**: ワーカー完了からメッセージスレッドの装着までの間、
  誰も強参照を持たず結果が即座に消える。完了コールバックも**結果の `shared_ptr` を強参照で
  捕捉**し、キャッシュ登録とクリップへの装着が済むまで保持する
- LRU から追い出しても、そのとき使っているクリップは自分の `shared_ptr` を持っているので
  音は消えない。上限が縛るのは**再利用のために取っておく分**だけ
- これで列挙された危険が全部消える: 消えたクリップは引きに来ない／分割・複製で指紋が変われば
  引き直す／同じ指紋のクリップ同士は**1本のバッファを共有できる**（複製がメモリを食わない）
- プロジェクト切替時はキャッシュを捨てる
- 追加コスト: 完了時に全クリップを1回走査して付け直す（クリップ数はせいぜい数百でO(n)）

`Clip::id` を足さない理由は、永続化・`ensureUniqueIds()`・JSON版数に波及するわりに、
指紋方式で同じ安全性がより少ない機構で得られるため。

#### 安全限界（音楽的な制限とは別に必ず要る）

「ハード制限なし」は**音楽的な品質の話**で、実装上の防御は別に要る。JSON手編集や計算異常で
ゼロ長・オーバーフロー・巨大メモリ確保が起きる。

**要求を受理する時点で検査し、通らない値は保存しない**:

- `std::isfinite(ratio) && ratio > 0` を設定時と読込時の両方で強制（外れたら 1.0 に落とす）
- `ratio` は実装上の上下限でクランプ（出力長とメモリの上限から逆算した値。音楽的な 0.9〜1.1 とは別）
- **層で振る舞いを分ける**: **要求受付層はクランプ**（ユーザー操作・JSON読込。値を直して受理する）、
  **`ClipStretcher` の直呼びは失敗を返す**（受付層を通っていない呼び出しを黙って通さない）
- `semitones` は ±12 にクランプ
- 出力長は `int64` で計算し、`int` へ渡す前に checked conversion

**「原音を返してごまかす」ことは絶対にしない**。100倍を要求したのに原音が鳴り、保存値だけ
100倍のまま残る状態を作ってしまう。

- 受理時に弾いた値は**要求値としても残さない**（クランプ済みの値が保存される）
- **受理の時点で出力長とメモリ上限まで検査する**。ここを通った要求は原則として成功するので、
  失敗は一過性（確保失敗・ライブラリが false を返す等）だけになる

**失敗しても「永続状態＝鳴っている音」を必ず保つ**。旧 render を維持したまま新しい要求値を
保存すると、`+2` が鳴っているのに `+3` が保存され、再読込で `+3` を再試行して失敗し
**どちらでもない音**になる。規則:

- レンダーが失敗したら、**要求値を「直前に成功していた値」へ戻す**（＝実効値へ巻き戻す）
- **巻き戻しの適用先は「現在の要求指紋が、失敗した指紋とまだ一致するクリップ」だけ**。
  `+2` の実行中に `+3` へ変えて古い `+2` が失敗した場合、`+3` を巻き戻してはいけない
  （一致しないものはログだけ）
- 前例が無い場合は**要求値を `0` / `1.0` に戻し、`activeDomain` も無加工にする**
- **分割はレンダーを伴わないので失敗し得ない**（ドメインを継承して view を切るだけ）。
  分割の原子性・ロールバック・pending 中の編集規則はいずれも不要
- いずれもトーストで知らせる。原音を「その指紋の生成結果」としてキャッシュしてはいけない

#### レンダリング要求の間引き（指紋の dedup だけでは足りない）

スライダーを動かすと `ratio` / `semitones` が毎回変わる＝**全部が別の指紋**になるので、
同一指紋の畳み込みでは滞留を防げない（古い100件を処理してから最新値が反映される）。

- **debounce を入れる**（150ms 程度。値が落ち着いてから積む）
- **待機キューの真実の源は「全クリップの要求指紋の集合」**にする。走査して集合を作り直し、
  **集合に含まれる指紋はすべて残す**。落とすのは**その指紋を要求するクリップが0件になったとき**だけ
- 「同じ原音範囲は最新1件だけ残す」は**採らない**: 同じ素材を複製して片方 `+2`・もう片方 `-2` に
  したとき、正当な要求の片方が消える
- 実行中の1件は完走してよい（中断は複雑さに見合わない）

#### 寿命管理（キャッシュを捨てるだけでは足りない）

キャッシュとキューを捨てるだけでは、**実行中のスレッドと、メッセージスレッドへ投げ済みの
コールバック**が破棄後の `RenderCache` / `MainComponent` に触れる。

- デストラクタで**停止要求 → join** する
- コールバック側は**プロジェクト世代（または weak な lifetime token）を確認**してから触る
- **プロジェクト切替の最中にレンダーが完了するテスト**を書く

- [x] **巻き戻しは必ず dirty 化する**（保存後に失敗するとディスクは新しい値・メモリは旧値になる）。

- **`exact()` を採用で確定**（手動 seek/flush は不要）。ただし入力が `outputSeekLength` 未満だと
  無音+false を返すため、**前後に原音の助走（先頭側は `outputSeekLength+interval`・末尾側は
  `inputLatency+interval`）を足し、出力の対応区間だけ切り出す**方式にした。20msチョップ・
  バッファ端接触・頭の無音の回帰テストで確認済み
- トナリティ上限は 8000Hz（signalsmith 付属 cmd の既定と同じ。音色維持の妥協点）
- 安全限界の実値: ratio 0.25〜4.0・出力 768MB 上限（`ClipStretchLimits`）。UI/JSON はクランプ受理・
