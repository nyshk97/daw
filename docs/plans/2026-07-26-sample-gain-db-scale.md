# サンプル音源GAINをdB等間隔スケールにする＋現在値の常設表示

## 概要・やりたいこと

サンプル音源トラックの詳細ビュー（`InstrumentDetailView`）のGAINには3つの問題がある。

### 問題1: 目盛りが耳に対して等間隔でない

内部の「線形倍率 0.0〜2.0」をそのままスライダーの値にしている。人間の耳は倍率でなく比率（dB）で音量を感じるため、倍率を等間隔に並べたスライダーは**耳にとって等間隔にならない**。

```
【現状】位置と「倍率」が等間隔
位置:  0%    25%    50%    75%   100%
倍率:  0     0.5    1.0    1.5    2.0
dB : -∞   -6dB    0dB  +3.5dB  +6dB
      └────────┘└──────────────┘
       1目盛りで6dB    1目盛りで3.5dB   ← 動く量がバラバラ

【変更後】位置と「dB」が等間隔
位置:  0%    25%    50%    75%   100%
dB : -12dB  -6dB    0dB   +6dB  +12dB
      └─────┘└─────┘└─────┘└─────┘
        どこを掴んでも 1目盛り＝6dB    ← 一定
```

下げ側（左半分）に「-∞〜0dB」が全部詰まっていて少しだけ下げたいときに狙いにくく、上げ側は幅が広いのに+6dBまでしか行かない。「買ってきた素材の音量がバラバラ」を吸収するというGAINの本来の用途に対して解像度が足りていない。

### 問題2: 今いくつに設定しているか分からない

dB値はドラッグ中のポップアップにしか出ないため、手を離すと現在値が読めない。つまみの位置だけでは基準（0dB）がどこかも分からない。

### 問題3: リセット手段が発見できない

ダブルクリックで0dBに戻せるが、画面上に手掛かりがない。GAINは頻繁に触る場所ではないので、この操作は忘れる前提で設計する必要がある。かといってリセットボタンを増やして行をごちゃつかせたくない。

### GAINの位置づけ（他DAWと同じで、ここは変えない）

```
サンプル素材 →[ GAIN ]→ 音源 →[ トラックフェーダー ]→ 曲
               ↑                     ↑
       素材のばらつきを直す      曲の中でのバランスを決める
```

素材ごとの音量差をGAINで先に吸収しておくことで、トラックフェーダーを0dB付近から始められ、フェーダーの位置＝ミックスの意図として読めるようになる。

### 既存プロジェクトの実データ（確認済み）

`~/Music/daw/*/project.json` の11プロジェクトを走査した結果、`sampleGain` の実値は以下の3種類だけ：

```
2件  "sampleGain": 1.0
1件  "sampleGain": 1.000139474868774
1件  "sampleGain": 0.775181353092194
```

→ **-12dB（≒0.2512倍）を下回る値も、+12dB（≒3.981倍）を超える値も1件も存在しない**。よって読み込み時に上下ともクランプしても、既存プロジェクトの音は変わらない。

### 他DAWの仕様（調査済み）

- どのDAWも「サンプル素材のトリム」と「トラックフェーダー」を別階層として持つ（Logic Sampler＝ゾーン/グループ/インストゥルメントの3段、Ableton Simpler、FL の PRE-AMP、Kontakt の Zone/Group/Instrument）
- トリムのUI作法: **dB表記・0dBがデフォルト・ダブルクリックでリセット・範囲は±12〜24dB程度**
- トリムに `-∞`（無音）は持たせないのが通例。消音はミュート/フェーダーの仕事で、トリムに無音域を割くと有効解像度が無駄になる
- 波形表示にゲインは反映しないのが多数派（波形は頭カット位置・減衰の形を見るためのもの）

### 決定事項

- **範囲は ±12 dB**。中央がちょうど0dBになるので、つまみ位置を見ただけで上げ/下げが分かる。買ってきた素材で12dB以上下げたいケースは稀で、そこまで行くならフェーダー側で処理する
- **保存形式は線形倍率のまま**（`sampleGain`）。project.jsonのバージョンは上げない。dB化はUI層だけの話にとどめ、オーディオ側（`SamplerEngine`）も変更しない
- **読み込み時に上下ともクランプする**。UIのスライダーが表現できない値をモデルに残すと「表示は-12dBなのに実際は-20dBで鳴る」という乖離が起きるため、範囲外の値は読み込み時点で範囲内へ寄せて表示と実音を必ず一致させる。実データに範囲外は0件なので既存プロジェクトへの影響はない
  - 副作用として、もし `sampleGain: 0.0`（無音）のプロジェクトがあれば-12dBで鳴り出すことになるが、実データに存在せず、そもそも無音はミュートで表現すべきものなので許容する
- **値域・dB⇄倍率変換・吸着ロジックは `Source/shared/GainScale.h` に純粋関数として切り出す**。`Project.cpp`（クランプ）と `InstrumentDetailView`（スライダー）の両方から使う単一の真実の源にし、UIを起動せずにテストできるようにする（`Shortcuts.h` がショートカット定義の単一の真実の源になっているのと同じ流儀）
  - 上限は概数の `4.0f` ではなく `Decibels::decibelsToGain(12.0f)` から導く（仕様上の最大値を正確に保つ）
  - `Decibels::decibelsToGain` は `std::pow` を使う非constexpr関数なので、`inline const float` 変数にせず**関数として提供する**（`Theme.h` に記録されている「inline変数の初期化順序でゼロを拾う」事故と同種のリスクを避ける）
- **見た目は案A（センター起点フィル）を採用**。HTMLモックで4案を比較して決定
  （モック: `/private/tmp/claude-501/-Users-d0ne1s-daw/c3325d6e-7b95-4262-8357-48218b9d180d/scratchpad/gain-ui-mock.html`）
  - 0dBを起点に、上げれば右へ・下げれば左へ帯が伸びる。**0dBのときは帯が消える**＝「素のまま」が一目で分かり、通常時はむしろ今より静かになる
  - FXパネルのPanノブが既に「センター起点の緑アーク」（`Theme::panArcGreen`）で同じ読み方をしているので、アプリ内で一貫する
- **リセット専用ボタンは置かない**。常設の数値表示自体をクリック可能にして役割を兼ねさせる（要素が増えない）。ホバーで薄い枠を出して押せることを示し、ツールチップで「クリックで 0 dB に戻す」と明示する
- **常設の数値表示**は行の右端にある「頭カット 0.0 ms」と同じ字送り・同じ色（`Theme::lcdLabel` / `Fonts::small()`）で並べ、新参者に見えないようにする。0dB以外のときだけ文字を明るくして「デフォルトから外れている」を示す
- **0dB付近の吸着はドラッグ中だけ効かせる**。`juce::Slider::snapValue (double, DragMode)`（`juce_Slider.h:856` にvirtualで実在）をoverrideした専用Slider派生で実装し、`dragMode != notDragging` のときだけ±0.3dBを0へ寄せる。プログラムからの同期（`refreshFromModel`）や数値クリック/ダブルクリックでのリセットは吸着の対象にしない
- 常設dB数値についてCLAUDE.mdは「ミキサー/FXパネルのみ。常時見えるヘッダーには置かない」としているが、ここは下部詳細エディタなので方針と矛盾しない（同じ行に「頭カット 0.0 ms」の前例がある）

### 今回のスコープ外

- **Normalizeボタン**（波形のピークを測って最適GAINを自動で入れる）— 実データを測ったうえで**作らない判断をした**（2026-07-26）。根拠と再検討のトリガーはログの「Normalizeボタンを作らない判断」に記録

## ログ

### 試したこと・わかったこと

- **既存プロジェクトの実データは範囲内だけだった**: `~/Music/daw/*/project.json` 11件の `sampleGain` は `1.0`／`1.000139`／`0.775` のみ。-12dB未満・+12dB超は0件で、下限クランプを入れても既存の音は変わらない
- **ダブルクリックリセットは既に正しく動いていた**: `juce::Slider` の `mouseDoubleClick` は内部で `ScopedDragNotification` を張るため（`juce_Slider.cpp:1117`）、`onDragStart`/`onDragEnd` を経由する＝undoスナップショットと確定通知が走っていた。「モデルは変わるが音と保存に反映されない」という懸念は誤りで、余計な修正は入れていない
- **`AppLookAndFeel` はヘッダオンリーなのでテストから直接描画できる**: `daw_tests` は `ScopedJuceInitialiser_GUI` を持っているので、`drawLinearSlider` を `juce::Image` に描いてピクセルを数えれば、アプリを起動せずに見た目を検証できる

### Normalizeボタンを作らない判断（2026-07-26）

**測定**: `ffmpeg -af volumedetect` で実素材のピークを測った。

| 母集団 | n | ピーク中央値 | ピーク-3dB以上 |
|---|---|---|---|
| Logic付属サンプル（ランダム抽出） | 200 | -1.0 dB | 75% |
| 購入したビート素材（`OS_*`） | 3 | -1.0 dB | 100% |

**わかったこと**:

- 「市販素材は正規化済み」は4分の3にしか当てはまらない（当初n=4で断定したのは誤り）
- ただし**ピークが低い25%の正体はドラムキットのワンショット**（`Hi-Hat_1_CrateDigger_GB` -21.7dB、`Shaker_2_Seismic_GB` -19.9dB、`Kick_2_CrateDigger_GB` -10.3dB 等）。キット内での音量バランスが**意図的に**付けられており、個別に正規化するとバランスが壊れる（Reaperの "Normalize items to common gain" はこの問題への標準的な答えだが、LaLaは1トラック1サンプルなので複数選択の概念自体がない）
- ユーザーが実際に使う購入パックは正規化済み＝**Normalizeを押しても動くのは1dB以下**

**フェーダーとの関係（実質の制約は上げ側だけ）**:

- LaLaのフェーダーは `setRange(0.0, 1.0)` の線形倍率＝**-∞〜0dBでブーストできない**（Logicのフェーダーは+6dBまで上げられるので、ここは実はLogic準拠から外れている）
- 素材が**大きすぎる**場合はフェーダーで下げられる＝GAINの下げ側が何dBでも問題ない
- 素材が**小さすぎる**場合はフェーダーが使えず、**GAINの+12dBだけが頼り**

**決定**: Normalizeボタンは作らず、GAINの範囲も±12dBのまま据え置く。GAINがdBスケール＋数値表示で狙って動かせるようになった今、ボタンを増やす価値が薄いため。購入パック中心の使い方なら+12dBで足りる（Logic付属のドラムキット素材には届かないが、Apple純正音源の代替はCLAUDE.mdで非目標）。

**再検討のトリガー**: 実際に「GAINを最大にしても小さい」素材に出くわしたとき。そのとき次のどちらかを選ぶ。

- GAINの上限を+24dBへ広げる → ただし0dBがスライダー中央でなくなり、センター起点フィルの「中央＝0dB」という直感が崩れる（帯の起点を0dB位置に変える実装変更も要る）
- フェーダーを+6dBまで上げられるようにする（Logic準拠に戻す）→ 全フェーダー（ヘッダー・ミキサー・FX）のカーブ見直しとセットになる

### 方針変更

- **見た目の検証をスクショのピクセル差分からオフスクリーン描画テストに変更した**: アプリのウィンドウを撮って比較する方式は、ウィンドウ位置・レイアウト・撮影条件に依存して壊れやすい。`AppLookAndFeel::drawLinearSlider` を直接 `juce::Image` に描いて帯の位置・長さを数える方式にしたことで、再現可能な形でCIに残せるようになった（`gain slider center fill`）。Phase 0 で撮った基準画像は使わずに済んだ
- **アプリを起動しての目視確認を人間確認へ移した**: 起動中のdev版（PID 31273）は未保存の変更があり、quitすると保存ダイアログでユーザーの作業を止める。シングルインスタンス設計（`Main.cpp:72`）のため別インスタンスも立てられない。またユーザーが在席中のため合成マウスも撃たない判断をした
