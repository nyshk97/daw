# ループ先行トラック ①〜③ — ライブラリ調達・おすすめ5 CLI・ベースのループ追従・Loopsタブ

issue: [#5](https://github.com/nyshk97/daw/issues/5) / 設計の真実の源: `docs/design/reference-beat.md`「音色の調達」節（2026-08-07 の壁打ち・/dig で確定）

## 概要・やりたいこと

リファレンス駆動ビートメイクの最終形フロー

1. リファレンスを分析（既存: card.json＋report.md）
2. **上モノのループをおすすめ5から選ぶ** → 採用ループのキー/BPM をプロジェクトへ逆コピー
3. カード＋採用ループを制約に**ドラム・ベースの MIDI を生成ガチャ**（ベースはループ追従）
4. 各パーツの音色（ワンショット）もおすすめ5から選ぶ ← 後続 plan（④サンプラー）

のうち、**1〜3 を成立させる**。上モノは MIDI 生成でなくループ素材（買い切りパック中心・
iCloud Drive のグローバルライブラリ）を検索で引く。トリガー式はやめて連続着手に切り替え済み。

このplanの範囲: **①調達・セットアップ（人間作業）＋②Pythonペア（おすすめ5 CLI・ベースのループ追従）＋③Loopsタブ**。
④ワンショットサンプラー＋音色おすすめ5・⑤タイムストレッチ/トランスポーズは後続 plan（着手時に軽い dig）。
おすすめ5の対象も今回は **loops のみ**（ワンショットのレーン別おすすめは④で。④まで使わない機能を先回りしない）。

## 前提・わかっていること

### 方針（/dig で確定）

- **音色は全部ファイルで持つ**。プラグインホスティング・シンセエンジンは不採用。SFZ は保留棚
- **808 は独立パーツではなくベースの音色**。ベースガチャの MIDI は1本で、GM ベースで鳴らすか
  808 ワンショット（④で実装）で鳴らすかは音色差し替えの問題
- **おすすめ5 は決定的**（特徴量ランキング）。提示は**ページング型**（「次の5本」で6位以降）。
  温度付きランダムは混ぜない
- **逆コピーは確認ダイアログ付き**（分析完了ダイアログの「BPM とキーを設定」と同型・
  ルート/モードの保険付き）
- **ベースのループ追従は自動発動**: 採用ループがプロジェクトにあれば進行はループのルート列に
  固定（リズムだけガチャ）。ループ未採用ならカード駆動（従来どおり）
- 理由表示・CLI出力は**内部用語を使わない**（恒常ルール。重心→「明るさ」等の平易語）

### 方針（プランレビュー 2026-08-07 で確定）

- **採用ループは同時1本まで**（＝ハーモニーアンカー）。2本目以降のループは通常のオーディオ
  取り込みで敷けるが、アンカー（ベースが従う対象・逆コピーの源）にはならない
- **採用ループのメタデータは project.json に永続化する**（下記「永続化」）。ルート列は
  採用時に1回検出して保存し、ベースガチャは保存済みの値を読む（毎回再検出しない）
- **採用操作は「試聴（▶）と採用（明示ボタン）の分離」を第一候補**とし、Phase 4 前に
  HTML モックで確定する（Drums/Bass の「行クリック＝仮配置」と意味論が変わるため、
  見た目で判断してから実装する）

### コード調査の結果（実装の土台と、土台に無いもの）

- **ループ敷きは今日から可能**: ⌘R（リピート・Logic 同様連打で伸びる）・⌘C/⌘V（再生ヘッドへ
  ペースト）実装済み。クリップの移動・トリムが無くても運用は成立
- **取り込みは必ず `clip-NNN.wav` コピー**（`AudioImporter` が一時ファイル→リネーム経路）。
  自己完結は保たれるが、**元ファイル名（キー/BPM）・出自の情報はこの経路では消える** —
  だから永続化が必要（下記）
- **`bass.py` に外部注入の前例**: `--kick-ticks` / `--drums`。ルート列注入も同型の口で足せる。
  完全決定的・レーン別 seed（prog / rhythm 分離）
- **`topline.py` の CLI は流用できない**（stem＋bass＋basics＋outdir 前提・進行の畳み込みは
  2反復未満で空になる＝1周しか無いループで全滅）。流用できるのは**関数レベル**
  （chord_templates / match_chord）のみ。ループ用アルゴリズムは新規（Phase 3 に明記）
- **GachaSession の仮配置は MIDI ノート専用**（`previewCandidate()`）。音声クリップの
  仮配置は新規実装。既存の音声取り込み完了処理は独自 undo＋即保存で、ガチャの
  仮配置・一括 Keep と衝突するため流用不可 — **Loops タブは既存パーツへの「+1」ではない**
- **GachaSession の baseline は tracks のみ**保存。BPM/キーを含むセッション単位の
  トランザクションは新規（Phase 4 に明記）
- **試聴の下地**: `Source/audio/AudioFilePreview` が既存（AudioFileBrowserView で使用中）

### ライブラリの形

```
~/Music/daw/library → ~/Library/Mobile Documents/com~apple~CloudDocs/daw-library/  (symlink)
    ├── loops/<パック名>/       # リネーム禁止（ファイル名の Am_82bpm 等が主メタデータ）
    ├── oneshots/<パック名>/    # 置き場だけ用意。今回はインデックス対象外（④で+1）
    ├── _contrast/
    │   ├── loops/<パック名>/     # レコメンド検証用のジャンル外ループ
    │   └── oneshots/<パック名>/  # 同ワンショット（④の検証で使う）
    └── index.json              # インデックス（特徴量込み・マシン間で同期される）
```

- index.json の要件: **ライブラリ相対パス**（絶対パス禁止・マシン間同期のため）・
  `kind`（loop/oneshot）と `isContrast` を明示・schema version・一時ファイル→rename の
  原子的書き込み・追加/削除/更新の差分反映
- eviction 対策: ライブラリフォルダに Finder「ダウンロードを保持」を必ず指定
- 市販サンプルはアプリ成果物に同梱しない（royalty-free の再配布禁止）

### 永続化（project.json 変更）

採用ループの情報はクリップの `clip-NNN.wav` 化と「残す」で失われるため、project.json に保存する:

- **アンカーは Project 所有の「採用素材」で、クリップとは独立**（プランレビュー2回目で確定）。
  由来クリップを全部消してもアンカーは残り、消えるのは Loops タブでの**差し替え**か
  **明示解除**のみ。Clip に安定IDは足さない
- クリップ側の「採用ループ由来」フラグ＋ライブラリ相対パスは**出自表示専用**。
  分割・複製・ペーストで構造体コピーにより継承されるが、ライフサイクルには関与しない
- プロジェクト側（アンカー1本・プロジェクト直下）: ライブラリ相対パス・ループの BPM・キー・
  ループ小節数・検出済みルート列と信頼度
- **project.json version を +1**（v13→v14）。旧形式読み込み（フィールド無し＝アンカー無し）と、
  保存→再読込→ベースガチャが追従し続けることのテストを含める

**ルート列の JSON 契約**（永続化・looproots.py・bass.py の3者で共有。looproots.py の
docstring を単一の真実の源にし、3者のテストで固定する）:

- ルートは **0..11 の整数**（プロジェクトキーの root と同じ表現。音名文字列は使わない）
- `slots_per_bar`（chords カードと同じ意味）・`loop_bars`・`roots`（長さ =
  `loop_bars × slots_per_bar` 必須）・`confidence`（スロット別の配列。全体値は持たない）
- `--bars` がループ長を超える場合は**ループ反復**（chords カードの既存規則と同じ）
- 長さ不一致・範囲外の値は**即エラー**（黙った退化はしない。退化は「低信頼→トニックのみ」の
  1経路だけで、それは looproots.py 側の出力で表現する）

  キーを「契約があるときだけ」入れる方式にしたので、旧サイドカーの --from 再現は無傷

### 方針変更

- テストは pytest でなく**素の assert スクリプト**（リポジトリの既存流儀。`mise run lib:test` /
  `gacha:test` に組み込み）。plan の「pytest」表記はこの意味に読み替える
- venv は新設せず `tools/reference/.venv` を共用（gacha と同じ方式。依存が部分集合のため）
- **BPM フィルタの倍/半分テンポ許容を撤回**（2026-08-08 実装レビュー）: 160bpm 表記のループを
  80bpm 相当として薦めると、採用時の逆コピーでどちらを入れるかが未定義になる。±10%のみ
  （設計文書どおり）に戻した。実地で表記倍のループが弾かれて困ったら逆コピー意味論とセットで再検討
- **単音の退化判定を追加**（同レビュー）: テンプレート照合スコアだけだと A 単音が "A5" に 0.85 で
  一致しメロディをルート列として採用してしまう。有効ピッチクラス数（1音=0・2音=半減・3音以上=満額）を
  信頼度に掛けて plan の「単音フレーズはトニック退化」を成立させた
- 同レビューの他の反映: --roots 時は prog seed を 0 に正規化（同じ音の候補が別名で増えない・
  rhythm ロックで1件に畳まれる）／index と upper-features キャッシュの mtime を ns 精度に
  （同サイズ・同秒内の上書きを検出）／特徴抽出→rank の実 wav end-to-end テストを追加
- **単音判定をフレーム単位に修正**（2026-08-08 レビュー2周目）: スロット平均のクロマで
  ピッチクラス数を数えると、スロット内を動く単音メロディが3音以上に見えて和音扱いになる
  （8音メロディで実測）。時間フレームごとの同時発音数の中央値で判定する形に変更し、
  スロット内移動メロディの退化テストを追加。BPM フィルタの下限も 1/1.1（≈0.909）→ 0.90 に修正
  （−10%ちょうどの素材を弾いていた。境界72/80・88/80のテストを追加）
